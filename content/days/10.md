      ## REPL — 交互式对话主循环

      REPL（Read-Eval-Print Loop）是交互式编程环境的经典范式，从 Lisp 发明者 John McCarthy 1958 年的创造开始，几乎所有编程语言都提供 REPL。Claude Code 的 `REPL` 类把 REPL 范式和 Agent 系统结合在一起——用户输入消息，程序交给 AI 处理，打印 AI 的回复，然后继续等待下一条消息。

      ```python
      class REPL:
          def __init__(self):
              self.history = ConversationHistory()
              self.counter = TokenCounter()
              client = Anthropic(api_key=os.environ.get("ANTHROPIC_API_KEY", "sk-test"))
              registry = get_registry()
              registry.clear()
              registry.register(BashTool())

          async def run(self):
              print("Claude Code — REPL 对话")
              print("输入消息与 Claude 对话，输入 /help 查看命令，/exit 退出\n")

              while True:
                  try:
                      user_input = input("你: ").strip()
                  except (EOFError, KeyboardInterrupt):
                      print("\n再见!")
                      break

                  if not user_input:
                      continue

                  # 处理内置命令（不走 AI）
                  if user_input.lower() in ("/exit", "/quit", "/q"):
                      print("再见!")
                      break
                  if user_input == "/help":
                      print("可用命令: /help, /exit, /clear, /cost")
                      continue
                  if user_input == "/clear":
                      self.history.clear()
                      print("历史已清空")
                      continue
                  if user_input == "/cost":
                      print(self.counter.summary())
                      continue

                  # 正常消息 → 交给 AI
                  print(f"[模拟 AI 回复]: {user_input}")
      ```

      几个值得注意的细节：

      1. **`EOFError` 和 `KeyboardInterrupt` 的处理**：`input()` 在收到 Ctrl+D（Unix）或 Ctrl+Z+Enter（Windows）时会抛出 `EOFError`；收到 Ctrl+C 时抛出 `KeyboardInterrupt`。优雅地捕获这两个异常可以给用户一个友好的退出体验，而不是打印冰冷的 Python traceback。

      2. **`registry.clear()`**：初始化时清空注册表，确保每次启动 REPL 都是干净的状态，不会残留之前测试注册的临时工具。

      3. **内置命令优先于 AI**：所有 `/` 开头的命令（`/exit`、`/help`、`/clear`、`/cost`）都在调用 AI 之前拦截。这么做有两个原因：效率（不需要为简单命令付 API 费用）和可靠性（`/exit` 必须在 AI 响应之前执行，否则用户无法真正退出）。

      4. **`f"[模拟 AI 回复]: {user_input}"`**：这是教学版本的简化实现。真实的 `repl.py` 会在这里调用 `QueryEngine.run()` 并传入 `user_input`，AI 的真实回复会替换掉这个模拟字符串。

      5. **特殊命令的演进**：真实的 Claude Code 还会有更多命令（如 `/approval-mode`、`/model`、`/max-turns`），它们遵循同样的模式：先解析，再路由，每个命令对应一个处理函数。

# Day 10: 对话主循环 REPL

## 这一节要解决什么问题？

前面的课程我们已经构建了完整的 Agent 核心：工具系统、对话历史、API 调用、ReAct 循环。但这一切都需要一个**入口**来把它们串联起来。用户不能每次都写代码来调用 Agent——需要一个交互式界面，让用户能实时输入指令，看到 AI 的回复，就像使用命令行一样自然。

这个交互式界面叫做 **REPL**（Read-Eval-Print Loop）。名字里的四个词就是它的全部职责：**Read**（读取用户输入）→ **Eval**（处理/发送给 AI）→ **Print**（打印 AI 回复）→ **Loop**（回到起点继续等待）。这就是 Claude Code 的最外层——用户看到的命令行界面。

本节要解决的不只是"如何写一个 REPL"，更是**如何设计一个可扩展的命令系统**。Claude Code 支持很多特殊命令（`/exit`、`/clear`、`/cost`），以后还会加更多（切换模型、调整参数等）。如何让新命令的添加不影响现有代码？如何让 REPL 保持简洁但功能丰富？

## 概念图解

```
+----------------------------------------------------------+
|                  REPL 的四步循环                          |
+----------------------------------------------------------+

  ┌─────────┐
  │  READ   │  从终端读取用户输入
  │  input()│  "帮我写一个排序算法"
  └────┬────┘
       ↓
  ┌─────────┐
  │   EVAL  │  判断输入类型并执行
  │ 路由分发 │
  └────┬────┘
       ↓
  ┌─────────┐    ┌──────────────────────────────────┐
  │  /help  │    │        是特殊命令？               │
  │  /exit  │→YES│ → 调用对应处理函数（不走 AI）     │
  │  /clear │    └──────────────────────────────────┘
  │  /cost  │    NO ↓
  └────┬────┘    ┌──────────────────────────────────┐
       │         │        是普通消息                 │
       │         │ → history.addMessage(user, ...)  │
       │         │ → QueryEngine.run(message)        │
       │         │ → AI 返回回复文字                  │
       │         └──────────────────────────────────┘
       ↓
  ┌─────────┐
  │  PRINT  │  打印结果给用户
  │ console │  "Claude: 以下是快速排序实现..."
  └────┬────┘
       ↓
  ┌─────────┐
  │  LOOP   │  回到 READ，继续等待下一条输入
  └─────────┘


+----------------------------------------------------------+
|              Node.js readline 模块工作原理                  |
+----------------------------------------------------------+

  const readline = require("readline");

  const rl = readline.createInterface({
    input: process.stdin,    // 从键盘读取输入
    output: process.stdout,  // 输出到终端
  });

  // question() 是异步的：等待用户按回车，然后回调
  rl.question("你: ", answer => {
    console.log("用户输入了:", answer);
    rl.close();  // 关闭界面，结束程序
  });

  // Ctrl+C 会触发 KeyboardInterrupt
  // Ctrl+D 会触发 EOFError


+----------------------------------------------------------+
|              命令解析的扩展方式：命令表模式                 |
+----------------------------------------------------------+

  // 不用一堆 if/else，用字典做命令表（Command Pattern）
  const COMMANDS = {
    "/exit":   { handler: handleExit,   description: "退出程序" },
    "/help":   { handler: handleHelp,   description: "显示帮助" },
    "/clear":  { handler: handleClear,  description: "清空历史" },
    "/cost":   { handler: handleCost,  description: "查看成本" },
    "/model":  { handler: handleModel,  description: "切换模型" },  // 新命令！
  };

  function processInput(input) {
    const cmd = COMMANDS[input.trim()];
    if (cmd) {
      cmd.handler();  // 执行对应处理函数
      return true;     // 返回 true 表示"已处理，不需要走 AI"
    }
    return false;      // 返回 false 表示"不是命令，当作普通消息处理"
  }
  // 新增命令只需在 COMMANDS 表里加一行，不影响其他代码
```

## 基础知识

### 1. Node.js readline 模块

`readline` 是 Node.js 内置的终端输入处理模块，提供异步的键盘输入读取能力：

```js
const readline = require("readline");

const rl = readline.createInterface({
  input: process.stdin,   // 标准输入（键盘）
  output: process.stdout, // 标准输出（屏幕）
});

console.log("你好，请输入你的名字:");

// question() 是异步的：打印提示语后等待用户按回车
rl.question("> ", name => {
  console.log(`你好，${name}！`);
  rl.close(); // 关闭 readline 界面，程序正常退出
});

// 注意：如果不调用 rl.close()，程序会一直等待输入，不会退出
```

### 2. 命令行特殊键的处理

用户按 Ctrl+C 和 Ctrl+D 会产生特殊事件，REPL 需要优雅地处理它们：

```js
// Ctrl+C：发送 SIGINT 信号，Node.js 抛出 KeyboardInterrupt
process.on("SIGINT", () => {
  console.log("\n收到 Ctrl+C，正在退出...");
  rl.close();
  process.exit(0);
});

// Ctrl+D：发送 EOF，readline 抛出 EOFError
rl.on("close", () => {
  console.log("\n再见！");
  process.exit(0);
});

// readline.question() 内部捕获了 EOFError，
// 会把控制权交给我们，而不是让程序崩溃
rl.question("> ", answer => {
  if (answer === null) {
    // answer 为 null 表示收到了 EOF（Ctrl+D）
    console.log("收到 EOF");
    rl.close();
  }
});
```

### 3. 命令解析系统

用字典（Map）存储命令和对应的处理函数，比一堆 `if/elif` 更清晰、更易扩展：

```js
const COMMANDS = new Map([
  ["/exit",   { fn: () => { console.log("再见"); process.exit(0); } }],
  ["/help",   { fn: showHelp }],
  ["/clear",  { fn: () => history.clear(); console.log("历史已清空") }],
  ["/cost",   { fn: () => console.log(tokenCounter.summary()) }],
]);

function showHelp() {
  console.log("可用命令:");
  for (const [cmd, meta] of COMMANDS) {
    console.log(`  ${cmd.padEnd(10)} - ${meta.description}`);
  }
}

function handleInput(input) {
  const trimmed = input.trim();
  const cmd = COMMANDS.get(trimmed.toLowerCase());
  if (cmd) {
    cmd.fn();
    return true; // 已处理
  }
  return false; // 非命令，当作普通消息
}
```

## 进阶知识

### Tab 键自动补全

真实的 Claude Code REPL 支持按 Tab 键自动补全命令，这是 `readline` 的内置功能：

```js
const rl = readline.createInterface({
  input: process.stdin,
  output: process.stdout,
  completer: (line) => {
    const hits = COMMANDS.keys()
      .filter(cmd => cmd.startsWith(line)); // 过滤匹配的候选
    return [hits.length ? hits : [], line];  // [候选列表, 已输入部分]
  },
});

// 用户输入 "/" 后按 Tab → 显示所有 / 开头的命令
// 用户输入 "/cle" 后按 Tab → 自动补全为 "/clear"
```

### ANSI 转义序列：彩色输出

终端支持 ANSI 转义序列来控制文字颜色和格式，这些控制字符不会被用户看到，只会改变显示效果：

```js
// ANSI 颜色码
const colors = {
  reset:   "\x1b[0m",
  red:     "\x1b[31m",
  green:   "\x1b[32m",
  yellow:  "\x1b[33m",
  blue:    "\x1b[34m",
  bold:    "\x1b[1m",
};

function printColored(text, color) {
  console.log(`${colors[color]}${text}${colors.reset}`);
}

printColored("错误: 文件不存在", "red");
printColored("Claude Code REPL", "blue");
printColored("警告: Token 用量较高", "yellow");

// 注意：Windows 的老版本 cmd.exe 不支持 ANSI 颜色，
// 需要用 `colorette` 或 `ansi-colors` 等库做兼容处理
```

## 代码演示

```js
// 模拟 REPL（不需要真实 API Key）
class SimpleREPL {
  constructor() {
    this.history = [];
    this.running = false;
  }

  printWelcome() {
    console.log("=".repeat(50));
    console.log("  Claude Code — REPL 对话");
    console.log("=".repeat(50));
    console.log("输入消息和 Claude 对话");
    console.log("命令: /help, /exit, /clear, /history");
    console.log();
  }

  handleCommand(input) {
    switch (input.toLowerCase()) {
      case "/exit":
      case "/quit":
      case "/q":
        console.log("再见！");
        this.running = false;
        return false;

      case "/help":
        console.log("可用命令:");
        console.log("  /help    - 显示帮助");
        console.log("  /exit    - 退出");
        console.log("  /clear   - 清空历史");
        console.log("  /history - 显示历史");
        return true;

      case "/clear":
        this.history = [];
        console.log("历史已清空");
        return true;

      case "/history":
        if (this.history.length === 0) {
          console.log("（无历史）");
        } else {
          this.history.forEach((msg, i) => {
            console.log(`${i + 1}. [${msg.role}] ${msg.content.slice(0, 50)}...`);
          });
        }
        return true;

      default:
        return false;
    }
  }

  simulateResponse(userInput) {
    // 模拟 AI 回复
    const responses = [
      "收到！我理解了。让我帮你处理。",
      "这是个有趣的问题。我来分析一下……",
      "好的，我来执行这个任务。",
    ];
    return responses[Math.floor(Math.random() * responses.length)];
  }

  // 运行 REPL（Node.js readline）
  async run() {
    const readline = require("readline");
    this.running = true;
    this.printWelcome();

    const rl = readline.createInterface({
      input: process.stdin,
      output: process.stdout,
    });

    const ask = () => {
      if (!this.running) {
        rl.close();
        return;
      }
      rl.question("你: ", async (userInput) => {
        const input = userInput.trim();
        if (!input) { ask(); return; }

        // 先检查是否特殊命令
        const isCommand = this.handleCommand(input);
        if (!isCommand) {
          // 加到历史
          this.history.push({ role: "user", content: input });
          // 模拟 AI 回复
          const response = this.simulateResponse(input);
          console.log(`Claude: ${response}`);
          this.history.push({ role: "assistant", content: response });
        }

        ask();
      });
    };

    ask();
  }
}

// 运行
console.log("（Node.js readline REPL 需要真实终端环境）");
console.log("以下是模拟演示:");
const repl = new SimpleREPL();
repl.history.push({ role: "user", content: "你好" });
console.log("你: 你好");
console.log("Claude:", repl.simulateResponse("你好"));
console.log("\n输入 /help 查看所有命令");
```

## 知识点速查表

| 概念 | 说明 | 示例 |
|------|------|------|
| REPL | Read-Eval-Print Loop，交互式循环 | `input()` → 处理 → `print()` → 循环 |
| readline | Node.js 终端输入模块 | `readline.createInterface()` |
| `rl.question()` | 异步等待用户输入 | 等用户按回车后执行回调 |
| Ctrl+C / Ctrl+D | 中断信号和 EOF 信号 | 需捕获以优雅退出 |
| 命令表模式 | 用字典存储命令路由 | `COMMANDS.get(input)` |
| Command Pattern | 把命令封装成对象/函数 | 易于扩展新命令 |
| ANSI 颜色码 | 终端文字颜色控制 | `\x1b[31m` 红色，`\x1b[0m` 重置 |
| Tab 补全 | `completer` 函数过滤候选 | 按 Tab 显示所有 `/` 命令 |

## 面试题

**Q1: `rl.question()` 是异步的，但它内部的回调里又调用了 `ask()`，形成了递归。Node.js 的事件循环能正确处理这种递归模式吗？有没有可能造成栈溢出？**

提示：`ask()` 在 `rl.question()` 的回调里被调用，而 `rl.question()` 本身是异步的（不阻塞），所以这实际上不是真正的递归（每次调用在不同的 tick 中）。真正的递归是 `function foo() { foo(); }`，它同步调用自己。两者有什么区别？

**Q2: 如果用户在 AI 回复过程中（AI 正在"打字"时）按了 Ctrl+C，会发生什么？你的程序应该如何在 AI 流式输出时优雅地处理中断信号？**

提示：考虑两种场景：AI 还没开始回复（正在推理），以及 AI 正在流式输出（正在逐字打印回复）。
