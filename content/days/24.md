      ## MCPClient — MCP 协议客户端实现

      JS Demo 展示了 MCP 的整体架构（Claude Code 作为客户端，通过 MCP 协议连接多个 Server），而 Python 源码则展示了 MCP 协议的 JSON-RPC 2.0 规范在代码层面的实现。

      ### JSON-RPC 2.0 协议基础

      MCP 基于 JSON-RPC 2.0，这是远程过程调用（RPC）的一种简单格式。一个 MCP 消息的结构如下：

      ```json
      {
        "jsonrpc": "2.0",       // 协议版本，固定为 "2.0"
        "id": "1",               // 请求 ID，用于匹配响应
        "method": "tools/call",  // 方法名
        "params": { ... }        // 方法参数
      }
      ```

      响应结构：
      ```json
      {
        "jsonrpc": "2.0",
        "id": "1",
        "result": { ... }        // 成功时
        // 或
        "error": { ... }         // 失败时
      }
      ```

      ### MCPClient 的三个核心方法

      - **`_send()`**：低层方法，构造 JSON-RPC 请求体，通过 HTTP POST 发送到 MCP Server，用 `httpx.AsyncClient` 实现异步 HTTP 调用。
      - **`call_tool()`**：调用 MCP Server 上的工具，传入工具名和参数列表。
      - **`list_tools()`**：查询 MCP Server 暴露了哪些工具，返回工具描述列表。

      ### MCP 协议与 Claude Code 的关系

      在 Claude Code 中，MCP 扮演"连接层"的角色：Claude Code 是 MCP Client，每个外部数据源/工具是 MCP Server。当 Claude Code 需要查询数据库、访问 GitHub、操作 Slack 时，它不需要为每个数据源单独写集成代码——只需要连接对应的 MCP Server，通过统一协议通信即可。

      ### 安全考量

      MCP 请求通过 HTTP 发送到 Server URL。在生产环境中，Server URL 应该是 HTTPS，并且需要认证机制（如 API Key 或 JWT）。当前代码中的 `httpx.AsyncClient(timeout=30.0)` 也设置了 30 秒超时，防止请求无限等待。

# Day 24: MCP 协议

## 这一节要解决什么问题？

每个 AI 工具都要单独集成，代码乱七八糟。MCP（Model Context Protocol）提供统一标准，让 AI 能连接任何外部工具和数据源。

## MCP 核心概念

```
Claude Code ←→ MCP Client ←→ MCP Server A (文件系统)
                        ←→ MCP Server B (数据库)
                        ←→ MCP Server C (GitHub)
                        ←→ MCP Server D (Slack)
```

- **MCP Server**：提供工具和数据源的外部服务
- **MCP Client**：Claude Code 里的客户端，连接各个 Server
- **Protocol**：统一的通信格式，Server 开发者不需要知道 Claude Code 的实现

## 知识进阶：MCP 的设计动机

没有 MCP 之前，为 AI 添加一个新工具需要：

1. 在 Claude Code 源码中写集成代码
2. 处理该工具的认证、数据格式、错误处理
3. 每次工具 API 升级都要改 Claude Code

有了 MCP：

1. 工具开发者自己实现 MCP Server，遵守协议规范
2. Claude Code 只需要连接它，不需要了解内部细节
3. **关注点分离**：Claude Code 管好 AI 逻辑，工具管好自己的功能

这就像 USB 接口：不需要为每个设备写专门的驱动，只需要一个统一的 USB 协议。

### Python 真实源码解析

```python
# mcp_client.py — MCP 协议客户端实现

import json
import asyncio
import httpx                     # 异步 HTTP 客户端库
from dataclasses import dataclass
from typing import Any

# MCP 消息数据类：用 dataclass 规范消息结构
@dataclass
class MCPMessage:
    jsonrpc: str = "2.0"         # JSON-RPC 协议版本（固定值）
    id: str | None = None        # 请求 ID，用于匹配请求和响应
    method: str | None = None    # 方法名，如 "tools/call"
    params: dict | None = None   # 方法参数
    result: Any = None           # 成功响应结果
    error: dict | None = None   # 错误信息（失败时）


class MCPClient:
    """MCP 客户端：负责与单个 MCP Server 通信"""

    def __init__(self, server_url: str):
        self.server_url = server_url

    # 底层发送方法：构造 JSON-RPC 请求并发送
    async def _send(self, method: str, params: dict | None = None, id: str = "1") -> dict:
        payload = {"jsonrpc": "2.0", "method": method, "id": id}
        if params:
            payload["params"] = params
        # httpx.AsyncClient：异步 HTTP POST
        async with httpx.AsyncClient(timeout=30.0) as client:
            response = await client.post(self.server_url, json=payload)
            return response.json()

    # 调用 MCP Server 上的工具
    async def call_tool(self, tool_name: str, params: dict) -> dict:
        """
        向 Server 发送 tools/call 请求。
        params 包含工具名和具体参数。
        """
        return await self._send("tools/call", {"name": tool_name, "params": params})

    # 列出 Server 支持的所有工具
    async def list_tools(self) -> list[dict]:
        """
        向 Server 发送 tools/list 请求，获取工具清单。
        返回格式：[{name, description, inputSchema}, ...]
        """
        result = await self._send("tools/list")
        return result.get("result", {}).get("tools", [])
```

### 进阶：实现多 Server 管理器

```python
# 进阶：同时管理多个 MCP Server
class MultiMCPClient:
    def __init__(self):
        self.clients: dict[str, MCPClient] = {}

    def connect(self, name: str, server_url: str):
        """连接到新的 MCP Server"""
        self.clients[name] = MCPClient(server_url)

    async def call_tool(self, server_name: str, tool_name: str, params: dict):
        """在指定 Server 上调用工具"""
        client = self.clients.get(server_name)
        if not client:
            raise ValueError(f"未连接的 MCP Server: {server_name}")
        return await client.call_tool(tool_name, params)

    async def discover_all_tools(self) -> dict[str, list[dict]]:
        """发现所有已连接 Server 的工具"""
        results = {}
        for name, client in self.clients.items():
            results[name] = await client.list_tools()
        return results
```

```js
// MCP 客户端简化实现
class MCPClient {
  constructor() {
    this.servers = new Map();
    this.tools = new Map();
  }

  // 连接 MCP Server
  async connect(name, serverUrl) {
    console.log(`🔗 连接 MCP Server: ${name} (${serverUrl})`);
    this.servers.set(name, { url: serverUrl, tools: [] });

    // 模拟发现工具
    const discoveredTools = await this.discoverTools(name);
    for (const tool of discoveredTools) {
      this.tools.set(tool.name, { ...tool, server: name });
    }

    console.log(`✅ ${name} 连接成功，发现 ${discoveredTools.length} 个工具`);
  }

  async discoverTools(serverName) {
    // 真实环境：通过 MCP 协议发现工具
    // 模拟：返回一些工具
    return [
      { name: `${serverName}_query`, description: `查询 ${serverName} 数据` },
      { name: `${serverName}_write`, description: `写入 ${serverName} 数据` },
    ];
  }

  // 调用 MCP 工具
  async callTool(toolName, args) {
    const tool = this.tools.get(toolName);
    if (!tool) throw new Error(`工具不存在: ${toolName}`);

    console.log(`→ 调用 ${tool.server}/${toolName}`, args);
    return { success: true, data: "MCP 调用结果（模拟）" };
  }

  listTools() {
    return Array.from(this.tools.values()).map(t => ({
      name: t.name,
      description: t.description,
      server: t.server,
    }));
  }
}

// 使用
const mcp = new MCPClient();
mcp.connect("filesystem", "mcp://localhost:3001");
mcp.connect("github", "mcp://localhost:3002");

console.log("\n可用 MCP 工具:");
console.log(mcp.listTools());

mcp.callTool("github_query", { repo: "anthropics/claude-code", type: "issues" });
```

## 面试与延伸问题

1. **MCP 和 Function Calling（工具调用）有什么区别？** Function Calling 是 AI 模型根据对话内容决定调用哪些预定义函数，函数定义直接嵌入在 AI 请求中；MCP 是外部协议，AI 通过 MCP Client 连接独立的 MCP Server，Server 的工具清单是动态发现的，不需要重新训练模型。
2. **MCP Server 可以是本地进程吗？** 可以。MCP 支持多种传输方式：HTTP（远程）、STDIO（本地子进程）、WebSocket（长连接）。本地 STDIO 方式更安全，适合处理敏感数据。
3. **MCP 如何保证安全性？** MCP 支持 mTLS 双向认证、TLS + API Key、JWT 等机制。另外 MCP 有权限模型：Client 可以告诉 Server "这个请求来自哪个用户"，Server 据此限制数据访问范围。
4. **如果 MCP Server 宕机了怎么办？** MCPClient 应该实现重试逻辑（带指数退避）和熔断器（Circuit Breaker）模式，防止反复重试拖垮系统。
