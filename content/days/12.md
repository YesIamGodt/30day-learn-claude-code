      ## ContextManager — 上下文信息收集

      ContextManager 的核心职责是在每轮对话开始前，收集"当前状态快照"，并把它注入到系统提示词中。这个快照包含三个维度：

      1. **工作目录**（cwd）：AI 需要知道自己在哪个目录下执行命令，这是相对路径解析的基础
      2. **Git 分支**：很多项目操作与当前分支强相关，AI 如果不知道在哪个分支，可能误操作

      为什么不直接用命令获取这些信息？因为 Claude Code 是运行在用户本地环境中的，它天然能访问文件系统。关键设计是 **`__post_init__`** 方法——它和数据类初始化绑定在一起，确保 ContextManager 一创建，这些信息就是最新鲜的。

      `subprocess.run` 包裹在 `try/except` 中是必要的，因为 Claude Code 可能运行在没有 git 初始化的目录中，或者 git 命令不可用（Windows 某些环境）。这时优雅降级返回空字符串，比抛异常更合理。

      `build_system_prompt()` 是给 AI 看的信息格式。用 `\n` 分隔的键值对是简洁高效的格式，AI 容易解析，token 开销也不大。

# Day 12: 上下文窗口：AI 能记多少？

## 这一节要解决什么问题？

你有没有遇到过这种情况：AI 在长对话里突然"失忆"了，说的话前后矛盾，或者忘记了你们几分钟前刚讨论的内容？这不是 AI 变笨了，而是**上下文窗口**满了。

AI 的"记忆容量"是有限的，叫做**上下文窗口（Context Window）**。你可以把它理解为 AI 的一块"工作台"。Claude 3.5 Sonnet 的上下文窗口是 200K tokens，约等于 15 万个汉字，或者约 500 页书的文字量。听起来很大，但如果你的项目有几千行代码，加上几十轮对话，200K 很快就用完了。

当上下文窗口用完时，AI 会开始"忘记"早期对话。这就是为什么好的 Agent 系统需要**上下文管理**——知道什么时候该截断，什么时候该保留，保留什么。

## 上下文窗口就像工作台

想象你的桌子上只能放 200 张纸。你要同时处理一本书（项目代码）、一本手册（系统提示）、一叠便签纸（对话历史）。当纸太多时，你必须决定：

- 扔掉哪些旧便签（截断历史）
- 把多页内容合并成摘要（压缩历史）
- 哪些内容必须保留（关键上下文）

上下文管理器就是这个决策者。

## 概念图解

```
上下文窗口容量分配（200K tokens 示例）

┌──────────────────────────────────────────────┐
│  系统提示 (5K)  │  项目代码 (80K) │ 历史(100K) │  剩余(15K)  │
│  "你是 Claude"  │  主要源文件     │  对话记录  │  AI 思考空间 │
└──────────────────────────────────────────────┘

超过限制时，触发截断策略：
  1. 先扔最旧的历史消息
  2. 历史太旧 → 生成摘要压缩
  3. 摘要也超 → 截断代码文件（保留签名）
```

## 基础知识

### Token 估算

Token 是 AI 处理信息的基本单位。中文每个字约 1-2 个 token，英文每个单词约 1.3 个 token。精确计算需要调用 tokenizer，但在估算场景下可以用经验公式：

```js
// 经验估算：兼顾中英文
估算Token数(text) {
  const 英文词数 = text.split(/\s+/).length;           // 空格分词
  const 中文字符数 = (text.match(/[\u4e00-\u9fa5]/g) || []).length;  // 汉字匹配
  return Math.ceil(英文词数 * 1.3 + 中文字符数);        // 中文按 1 token/字算
}
```

### 分层截断策略

不同内容的重要性不同，截断的优先级也不同：

```
保留优先级（从高到低）：
1. 系统提示（不能截断，AI 不知道自己是 AI）
2. 最新用户消息（最相关）
3. 最新 AI 回复（包含工具调用结果）
4. 早期对话摘要（降级保留）
5. 旧对话详情（优先丢弃）
```

## 进阶知识

### 真实 Token 计数 vs 估算

经验公式的误差在 10-20%，对于粗略判断够用。但生产环境需要精确计数：

```python
# 真实 token 计数（需要 tiktoken 库）
import tiktoken
enc = tiktoken.get_encoding("cl100k_base")  # Claude 使用的编码
token_count = len(enc.encode(text))
```

为什么要区分？因为 token 不是简单的"字数"，而是 AI 模型训练时的切分单位。精确计数可以避免"以为还够用但实际已超"的情况。

### 上下文注入：给 AI 提供项目状态

Python 源码中的 ContextManager 在每轮对话前收集项目状态：

```python
def build_system_prompt(self) -> str:
    return (
        f"当前目录: {self.cwd}\n"       # AI 需要知道在哪执行命令
        f"Git 分支: {self.git_branch}\n"  # 分支信息影响操作上下文
        f"Git 状态: {self.git_status or '干净'}\n"  # 未提交文件影响风险判断
    )
```

这个方法的好处是：AI 每次思考时都自动带着"当前环境快照"，不需要用户主动说"我现在在哪个分支"。这大大减少了对话中的"无效废话"。

## 代码演示

```js
// 上下文管理器：跟踪窗口使用情况，在超限前主动截断
class ContextManager {
  constructor(maxTokens = 10000) {
    this.maxTokens = maxTokens;  // 上下文窗口上限（默认 10K）
  }

  // 估算一段文本的 token 数（中英文混合场景）
  估算Token数(text) {
    const 英文词数 = text.split(/\s+/).length;
    const 中文字符数 = (text.match(/[\u4e00-\u9fa5]/g) || []).length;
    return Math.ceil(英文词数 * 1.3 + 中文字符数);
  }

  // 计算整段对话的总 token 数（加 10 是元数据开销）
  估算消息总Token(messages) {
    return messages.reduce((sum, msg) => sum + this.估算Token数(msg.content) + 10, 0);
  }

  // 智能截断：从最旧的消息开始删，保留系统提示和最新消息
  截断到限制(messages) {
    let 总Token数 = this.估算消息总Token(messages);
    if (总Token数 <= this.maxTokens) {
      return messages;  // 还没超，不用截断
    }
    const result = [...messages];
    // 至少保留 2 条（系统提示 + 最近一条）
    while (this.估算消息总Token(result) > this.maxTokens && result.length > 2) {
      result.shift();  // 删除最早的消息（FIFO）
    }
    console.log(`⚠ 上下文超限，截断到 ${result.length} 条消息`);
    return result;
  }

  // 返回使用率统计和警告级别
  统计(messages) {
    const tokens = this.估算消息总Token(messages);
    const percent = Math.round((tokens / this.maxTokens) * 100);
    return {
      tokens,
      max: this.maxTokens,
      percent,
      警告: percent > 80 ? "⚠ 接近上限！" : percent > 50 ? "✓ 安全" : "✓ 充裕",
    };
  }
}

// 测试：模拟一段长对话
const manager = new ContextManager(500);  // 限制 500 tokens（测试用）
const 大量消息 = [
  { role: "system", content: "你是 Claude Code。" },
  { role: "user", content: "早上好！今天天气不错，我们开始工作吧。" },
  { role: "assistant", content: "好的，今天天气很好！请问需要我做什么？" },
  { role: "user", content: "帮我看看项目的 package.json。" },
  { role: "assistant", content: "package.json 内容如下..." },
];

console.log(manager.统计(大量消息));
// 输出: { tokens: 估算值, max: 500, percent: XX, 警告: "⚠ 接近上限！" }

const 截断后 = manager.截断到限制(大量消息);
console.log(`截断后: ${截断后.length} 条消息（保留系统提示 + 最新消息）`);
```

## 知识点速查表

| 概念 | 说明 |
|------|------|
| 上下文窗口 | AI 能同时处理的 token 上限（Claude 3.5 是 200K） |
| Token | AI 处理的基本单位，中文约 1-2 token/字，英文约 1.3 token/词 |
| 截断策略 | 超出窗口时，从最旧消息开始删除，保留系统提示 |
| 上下文注入 | 每轮对话前注入当前环境信息（目录、Git 状态等） |
| 估算 vs 精确 | 经验公式适合快速判断，生产用 tiktoken 精确计数 |

## 面试题

1. **如果对话历史已经 100 轮，直接截断前 80 轮会有什么问题？你会怎么做？**直接截断会丢失早期对话的关键信息（比如用户已经给了 AI 某些背景知识）。更好的做法是：先用 AI 对前 80 轮生成一个结构化摘要，再用摘要替换前 80 轮的内容，同时保留最近 20 轮完整对话。

2. **为什么系统提示不能被截断？能否让 AI 自动记住自己的身份？**AI 的"身份"是在训练时被赋予的，不是与生俱来的。如果上下文里没有系统提示，AI 会忘记自己是 Claude Code，可能回答说自己是什么都可以做的通用模型——这对用户来说是一个安全隐患。
