# Day 29: 测试与 CI

## 这一节要解决什么问题？

代码越改越多，一不小心就引入 bug。测试：每次改代码前先写测试用例，确保改动不会破坏现有功能。

## 测试金字塔

```
        /\
       /  \     E2E 测试（端到端）
      /----\    少量，耗时长
     /      \
    /   /\   \  集成测试
   /---/  \---\  较多
  /          \
 /     /\     \ 单元测试
/_____/  \_____\ 大量，速度快
```

## 知识进阶：为什么测试金字塔是这样的？

金字塔的每一层都有不同的特点和权衡：

| 层级 | 特点 | 数量 | 运行速度 | 调试难度 |
|------|------|------|---------|---------|
| **单元测试** | 测试单个函数/方法 | 最多 | 最快（毫秒级） | 简单 |
| **集成测试** | 测试多个模块协作 | 中等 | 中等（秒级） | 中等 |
| **E2E 测试** | 模拟真实用户操作 | 少 | 慢（分钟级） | 困难 |

Claude Code 的测试策略：
- **单元测试**：测试 TokenCounter、MemoryStore、FeatureFlagSystem 等纯函数逻辑
- **集成测试**：测试工具注册表的工作流（注册 → 调用 → 结果验证）
- **E2E 测试**：模拟完整的 REPL 对话流程（启动 → 输入 → 输出验证）

## 手动测试框架解析

```js
// 待测试的工具类
class TokenCounter {
  count(text) {
    // 英文单词数 * 1.3 + 中文字符数（估算 Claude token 消耗）
    const 英文 = text.split(/\s+/).filter(Boolean).length;
    const 中文 = (text.match(/[\u4e00-\u9fa5]/g) || []).length;
    return Math.ceil(英文 * 1.3 + 中文);
  }

  withinBudget(text, budget) {
    return this.count(text) <= budget;
  }
}

// 简单测试框架（核心原理）
function test(name, fn) {
  try {
    fn();
    console.log(`✅ ${name}`);
    return true;
  } catch (e) {
    console.log(`❌ ${name}`);
    console.log(`   ${e.message}`);
    return false;
  }
}

function assertEqual(actual, expected, message = "") {
  if (actual !== expected) {
    throw new Error(`${message} 期望 ${expected}，实际 ${actual}`);
  }
}

function assertTrue(value, message = "") {
  if (!value) {
    throw new Error(`${message} 期望 true，实际 ${value}`);
  }
}
```

## CI/CD 流程设计

```
代码提交（git push）
        ↓
触发 CI 服务器（GitHub Actions / GitLab CI）
        ↓
步骤 1：安装依赖（pip install / npm install）
        ↓
步骤 2：运行单元测试（pytest / jest）
        ↓
步骤 3：代码质量检查（ruff / eslint）
        ↓
步骤 4：安全扫描（bandit / npm audit）
        ↓
通过 → 自动部署到预发布环境
失败 → 通知开发者，阻止合并
```

### GitHub Actions 示例配置

```yaml
# .github/workflows/test.yml
name: Test
on: [push, pull_request]

jobs:
  test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-python@v5
        with:
          python-version: "3.12"
      - run: pip install -r requirements.txt
      - run: pip install pytest ruff bandit
      - run: pytest tests/ -v
      - run: ruff check src/
      - run: bandit -r src/
```

## 进阶：pytest 进阶技巧

```python
# tests/test_token_counter.py — 用 pytest 重写相同测试
import pytest
from src.day_29.token_counter import TokenCounter

class TestTokenCounter:
    """TokenCounter 的单元测试"""

    def setup_method(self):
        """每个测试方法前执行一次初始化"""
        self.counter = TokenCounter()

    def test_english_words(self):
        """英文单词计数"""
        assert self.counter.count("hello world") == 3  # 2 * 1.3 = 2.6 → 3

    def test_chinese_characters(self):
        """中文字符计数"""
        n = self.counter.count("你好世界")
        assert n >= 4  # 4 个中文

    def test_mixed_content(self):
        """混合内容"""
        n = self.counter.count("hello 你好 world 世界")
        assert n >= 6

    def test_within_budget(self):
        """预算检查"""
        assert self.counter.withinBudget("hello", 5)
        assert not self.counter.withinBudget("hello world", 1)

    @pytest.mark.parametrize("text,budget", [
        ("hi", 3),
        ("hello world", 5),
        ("你好", 3),
    ])
    def test_parametrized(self, text, budget):
        """参数化测试：一个测试函数覆盖多种输入"""
        assert self.counter.withinBudget(text, budget)
```

## 代码演示

```js
// 待测试的工具类
class TokenCounter {
  count(text) {
    const 英文 = text.split(/\s+/).filter(Boolean).length;
    const 中文 = (text.match(/[\u4e00-\u9fa5]/g) || []).length;
    return Math.ceil(英文 * 1.3 + 中文);
  }

  withinBudget(text, budget) {
    return this.count(text) <= budget;
  }
}

// 简单测试框架
function test(name, fn) {
  try {
    fn();
    console.log(`✅ ${name}`);
  } catch (e) {
    console.log(`❌ ${name}`);
    console.log(`   ${e.message}`);
    return false;
  }
  return true;
}

function assertEqual(actual, expected, message = "") {
  if (actual !== expected) {
    throw new Error(`${message} 期望 ${expected}，实际 ${actual}`);
  }
}

function assertTrue(value, message = "") {
  if (!value) {
    throw new Error(`${message} 期望 true，实际 ${value}`);
  }
}

// 测试用例
const counter = new TokenCounter();
let passed = 0;
let total = 0;

total++; passed += test("英文单词 Token 计数", () => {
  assertEqual(counter.count("hello world"), 3, "两个英文单词");
});

total++; passed += test("中文 Token 计数", () => {
  const n = counter.count("你好世界");
  assertTrue(n >= 4, "4个中文");
});

total++; passed += test("混合内容", () => {
  const n = counter.count("hello 你好 world 世界");
  assertTrue(n >= 6, "混合");
});

total++; passed += test("withinBudget: 在预算内", () => {
  assertTrue(counter.withinBudget("hello", 5));
});

total++; passed += test("withinBudget: 超预算", () => {
  assertTrue(!counter.withinBudget("hello world", 1));
});

console.log(`\n📊 测试结果: ${passed}/${total} 通过`);
```

## 面试与延伸问题

1. **什么是 TDD（测试驱动开发）？** TDD 的流程是：先写一个失败的测试（红色）→ 写最少的代码让测试通过（绿色）→ 重构代码。TDD 的价值在于强迫你在写代码前先思考接口设计，减少过度工程。
2. **mock（模拟对象）有什么用？** 单元测试要求"隔离"，不依赖外部系统。用 `unittest.mock.patch` 替换 `Anthropic` API 调用，返回预设的假数据，这样测试不需要真实的 API Key 和网络。
3. **测试覆盖率多少算够？** 没有绝对标准，一般建议 70-80% 以上。对于关键路径（认证、支付、数据写入）应该达到 90%+。但注意：覆盖率不是质量指标，100% 覆盖率不等于没有 bug。
4. **CI 中如何处理耗时的 E2E 测试？** 用测试优先级分层：PR 时只跑单元测试（快）；合并后定时跑全套 E2E；用并行化（`pytest-xdist`）和测试分组减少等待时间。
