      ## Skill — 技能系统

      这一节我们来认识 Claude Code 中两个最核心的数据结构：**Skill** 和 **SkillRunner**。它们共同构成了快捷指令的基础设施，让用户可以通过 `/skillname` 这样的斜杠命令快速触发预定义的工作流，而不必每次都写一大段提示词。

      ### Skill 的设计哲学

      `skill.py` 中定义了两个 dataclass：

      - **Step**：代表技能中的一个执行步骤，包含 `name`（步骤名）、`action`（动作描述）和 `params`（参数字典）。把一个复杂操作拆成多个步骤，便于管理和可视化。
      - **Skill**：一个技能的完整封装，由 `name`（唯一标识）、`description`（人类可读描述）和 `steps`（步骤列表）组成。

      这种设计的优势在于**组合性**：不同的 Skill 可以复用同一个 Step。例如 `review` 技能和 `refactor` 技能都包含"读取文件"这个步骤，只需要定义一次。

      ### SkillRunner — 技能的运行时

      `SkillRunner` 是技能的执行引擎，核心职责有三个：

      1. **注册（register）**：将 Skill 实例存入内部字典 `_skills`，以 name 为键。
      2. **查找（get）**：给定名称返回对应 Skill，找不到返回 `None`。
      3. **运行（run）**：异步遍历 Skill 的所有 Step，逐个执行并收集结果，返回一个字符串列表。

      注意 `run` 方法目前是**模拟执行**（只记录日志），真实场景下每个 Step 的 `action` 会对应一次 AI API 调用或一个工具调用。这就是为什么它设计为 `async` — 未来每个步骤都可能涉及 I/O 操作。

      ### 与 JS Demo 的对比

      JS 版的 Demo 侧重展示 Skill 系统的"用户界面"（`/review`、`/refactor` 等命令、模板变量替换 `{code}`），而 Python 版更贴近真实源码，展示了如何用 dataclass 规范数据结构，以及如何用 `async/await` 为真实的 AI 调用做准备。二者互为补充，一起理解才能看到全貌。

# Day 21: 快捷指令：把常用操作变成 /skill

## 这一节要解决什么问题？

每次让 AI "帮我代码审查"，要写一大段提示词。Skills 系统：把这些常用操作定义成快捷指令，`/review` 就搞定。

## Skills 工作流程

```
用户输入 /review
        ↓
SkillRunner 查找 "review" Skill
        ↓
找到对应 Skill，执行 steps 列表
        ↓
[Step 1] 读取代码文件
[Step 2] 调用 AI 审查
[Step 3] 输出结果
        ↓
返回结构化结果给用户
```

## 知识进阶：为什么需要结构化的 Skill？

手工写提示词有三个问题：

1. **重复劳动**：每次都写"你是一个代码审查员……"
2. **不一致**：不同人写出来的风格差异很大
3. **不可复用**：同一个提示词没法在多个场景使用

Skill 系统的核心思想是**把提示词模板化、步骤化**。通过 `{变量名}` 语法，每次调用时动态注入上下文；通过 `steps`，把一个复杂操作拆成可管理的小块。

### Skill 的数据结构

```python
# skill.py — Skill 数据结构（Python 真实实现）

from dataclasses import dataclass, field  # Python 内置的数据类装饰器
from typing import Any

# 单个执行步骤：描述技能中的一个操作单元
@dataclass
class Step:
    name: str                    # 步骤名称，如 "读取文件"
    action: str                  # 动作描述，如 "bash: ls -la"
    params: dict = field(default_factory=dict)  # 附加参数

# 完整技能：名称 + 描述 + 步骤列表
@dataclass
class Skill:
    name: str                    # 唯一标识，如 "review"
    description: str             # 人类可读描述
    steps: list[Step]            # 执行步骤列表

# SkillRunner：技能的注册表和运行时
class SkillRunner:
    def __init__(self):
        self._skills: dict[str, Skill] = {}  # 内部注册表

    # 注册技能到注册表
    def register(self, skill: Skill):
        self._skills[skill.name] = skill

    # 按名称查找技能
    def get(self, name: str) -> Skill | None:
        return self._skills.get(name)

    # 异步执行技能：遍历所有步骤并收集结果
    async def run(self, skill_name: str) -> list[str]:
        skill = self._skills.get(skill_name)
        if not skill:
            return [f"错误: Skill '{skill_name}' 不存在"]
        results = []
        for step in skill.steps:
            # 真实场景：这里会调用 AI 或执行工具
            results.append(f"[{step.name}] 执行: {step.action}")
        return results
```

### 进阶：如何实现带变量的模板

Python 版的 Skill 数据结构本身不处理模板变量替换，这部分在 JS Demo 中展示了实现思路。真实项目中可以这样扩展：

```python
# 扩展版：支持模板变量替换
class SkillRunnerWithTemplate(SkillRunner):
    def __init__(self):
        super().__init__()
        self.variables: dict[str, Any] = {}

    def set_variable(self, key: str, value: Any):
        """设置运行时变量"""
        self.variables[key] = value

    async def run_with_template(self, skill_name: str) -> list[str]:
        """执行技能并替换模板变量"""
        skill = self.get(skill_name)
        if not skill:
            return [f"错误: Skill '{skill_name}' 不存在"]

        results = []
        for step in skill.steps:
            # 用 format() 或模板引擎替换 {变量名}
            action = step.action
            for key, value in self.variables.items():
                action = action.replace(f"{{{key}}}", str(value))
            results.append(f"[{step.name}] 执行: {action}")
        return results
```

### 快速参考表

| 类/方法 | 作用 | 返回值 |
|--------|------|--------|
| `Step` | 单个执行步骤的数据类 | dataclass |
| `Skill` | 完整技能的数据类 | dataclass |
| `SkillRunner.register()` | 注册技能 | 无 |
| `SkillRunner.get()` | 查找技能 | `Skill \| None` |
| `SkillRunner.run()` | 异步执行技能 | `list[str]` |

## 代码演示

```js
class Skill {
  constructor(name, description, instruction) {
    this.name = name;
    this.description = description;
    this.instruction = instruction;
  }

  // 生成发给 AI 的提示
  toPrompt(context = {}) {
    return this.instruction.replace(/\{(\w+)\}/g, (_, key) => context[key] ?? "");
  }
}

class SkillSystem {
  constructor() {
    this.skills = new Map();
  }

  register(skill) {
    this.skills.set(skill.name, skill);
  }

  // 注册内置 skills
  registerDefaults() {
    this.register(new Skill(
      "review",
      "代码审查",
      `你是一个资深代码审查员。请审查以下代码，重点关注：
1. 潜在的 bug
2. 安全漏洞
3. 代码风格
4. 性能问题

代码：{code}`
    ));

    this.register(new Skill(
      "refactor",
      "代码重构",
      `你是一个重构专家。请重构以下代码，使其更清晰、更易维护。

原则：
- 保持功能不变
- 提升可读性
- 消除重复代码

代码：{code}`
    ));

    this.register(new Skill(
      "explain",
      "代码解释",
      `你是一个耐心的老师。请用通俗易懂的语言解释以下代码。

代码：{code}`
    ));
  }

  get(name) {
    return this.skills.get(name);
  }

  list() {
    return Array.from(this.skills.values());
  }

  // 处理 /skill 命令
  execute(skillName, context) {
    const skill = this.get(skillName);
    if (!skill) throw new Error(`未知 skill: /${skillName}`);
    return skill.toPrompt(context);
  }
}

// 使用
const skills = new SkillSystem();
skills.registerDefaults();

const reviewPrompt = skills.execute("review", { code: "const x = 1" });
console.log("生成的审查提示:");
console.log(reviewPrompt);
```

## 面试与延伸问题

1. **Skill 和 Tool 有什么区别？** Skill 是一组提示词模板 + 执行步骤，关注"做什么"；Tool 是具体的功能实现（调用 bash、写文件等），关注"怎么做"。
2. **如何实现技能的权限控制？** 在 `SkillRunner.run()` 中增加权限检查，例如检查 `skill.name` 是否在白名单中，或者检查用户角色。
3. **技能之间如何共享状态？** 可以通过 `SkillRunner` 的实例属性传递上下文，或者设计一个共享的 `Context` 对象在各 Skill 之间流动。
4. **如何实现技能的版本管理？** 给 `Skill` 增加 `version` 字段，在注册时检查版本号并执行升级迁移逻辑。
