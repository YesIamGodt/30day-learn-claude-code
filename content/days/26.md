      ## FeatureFlagSystem — 特性开关核心实现

      JS Demo 展示了特性开关的灰度逻辑（用 userId 的 hash 对 100 取模，决定是否在 rollout 百分比范围内），而 Python 源码更清晰地规范了特性开关的数据结构和启用判断逻辑。

      ### FeatureFlag 数据类

      用 `@dataclass` 定义了一个规范的数据结构：

      ```python
      @dataclass
      class FeatureFlag:
          name: str                    # 特性名称，唯一标识
          enabled: bool = False        # 是否全局启用
          rollout_percent: float = 0.0  # 灰度百分比，0-100
      ```

      这种设计支持三种灰度策略：
      - `enabled=False, rollout=0`：功能关闭
      - `enabled=True, rollout=100`：功能全量开启
      - `enabled=True, rollout=30`：功能灰度 30% 用户

      ### is_enabled 的判断逻辑

      判断顺序（短路求值）：

      1. 如果 flag 不存在 → 返回 `False`
      2. 如果 `flag.enabled == True`（管理员强制开启）→ 直接返回 `True`，忽略 rollout
      3. 如果 `rollout_percent > 0` → 用 `random.random() < rollout_percent` 决定（这是灰度逻辑）
      4. 否则 → 返回 `False`

      关键点：`enabled=True` 的优先级高于灰度 rollout。这意味着即使 rollout=0，只要 enabled=True，特性就开启。这是灰度管理的重要能力：先全员开启，再关闭问题用户。

      ### 灰度算法

      JS Demo 用字符串 hash（`Math.imul(31, h) + charCodeAt`）实现确定性灰度。Python 用 `random.random()`，每次调用结果不同。**生产环境推荐用确定性算法**，因为：
      - 同一用户多次访问应该得到一致的结果
      - 调试时能够复现问题
      - 可以精确控制哪些用户组在灰度范围内

      正确的确定性灰度公式：
      ```python
      hash_value = hash(user_id + flag_name)
      bucket = abs(hash_value) % 100
      return bucket < rollout_percent
      ```

# Day 26: 特性开关

## 这一节要解决什么问题？

发布新功能，直接上线风险大。特性开关（Feature Flags）：先让 5% 的用户用到新功能，观察没问题再全量开放。

## 特性开关的三种状态

```
特性开关状态机：

   ┌──── 全关（enabled=False, rollout=0）────┐
   │                                        │
   │    ┌──── 灰度中（rollout=30%）────┐     │
   │    │  根据 userId hash 决定       │     │
   │    │  30% 用户 → 开启            │     │
   │    │  70% 用户 → 关闭            │     │
   │    └──────────────────────────┘         │
   │                                        │
   └──── 全开（enabled=True 或 rollout=100）─┘
```

## 知识进阶：特性开关的工程价值

特性开关不只是"灰度发布"工具，它在整个软件工程生命周期中都有重要价值：

| 使用场景 | 说明 |
|---------|------|
| **灰度发布** | 新功能先让小部分用户试用 |
| **A/B 测试** | 不同用户看到不同版本，测量转化率 |
| **快速回滚** | 出问题时一键关闭，不需要重新部署 |
| **金丝雀发布** | 先上新版本给内部用户，再扩到外部 |
| **会员功能** | 不同订阅等级的用户看到不同功能 |

### Python 真实源码解析

```python
# feature_flags.py — 特性开关核心实现

from dataclasses import dataclass
import random

@dataclass
class FeatureFlag:
    """
    单个特性开关的数据结构。
    name: 特性名称
    enabled: 是否全局强制启用（优先级高于 rollout）
    rollout_percent: 灰度百分比，0-100，0 表示关闭，100 表示全量
    """
    name: str
    enabled: bool = False
    rollout_percent: float = 0.0


class FeatureFlagSystem:
    """
    特性开关系统：管理所有特性开关的状态。
    """

    def __init__(self):
        self._flags: dict[str, FeatureFlag] = {}

    def set(self, name: str, enabled: bool = False, rollout: float = 0.0):
        """
        注册或更新一个特性开关。
        Args:
            name: 特性名称
            enabled: 是否全局启用
            rollout: 灰度百分比（0-100）
        """
        self._flags[name] = FeatureFlag(name=name, enabled=enabled, rollout=rollout)

    def is_enabled(self, flag_name: str, user_id: str = "") -> bool:
        """
        判断某个用户是否应该看到某个特性。
        判断顺序：
        1. flag 不存在 → False
        2. enabled=True → True（强制开启）
        3. rollout>0 → 随机决定（灰度）
        4. 其他 → False
        """
        flag = self._flags.get(flag_name)
        if not flag:
            return False
        if flag.enabled:
            return True
        if flag.rollout_percent > 0:
            # random.random() 返回 [0.0, 1.0) 的浮点数
            # 如果小于 rollout_percent，则开启
            return random.random() < flag.rollout_percent
        return False
```

### 进阶：实现确定性灰度（生产推荐）

```python
# 确定性灰度：基于 hash，保证同一用户每次结果一致
import hashlib

class DeterministicFeatureFlagSystem(FeatureFlagSystem):
    def is_enabled(self, flag_name: str, user_id: str = "") -> bool:
        flag = self._flags.get(flag_name)
        if not flag:
            return False
        if flag.enabled:
            return True
        if flag.rollout_percent > 0:
            # 用 MD5 hash 保证确定性
            bucket = int(hashlib.md5(f"{user_id}:{flag_name}".encode()).hexdigest(), 16) % 100
            return bucket < flag.rollout_percent
        return False

    # 预览：某特性在不同用户间的分布情况
    def preview_distribution(self, flag_name: str, sample_users: list[str]) -> dict:
        """预览灰度分布（用于发布前检查）"""
        enabled = sum(1 for u in sample_users if self.is_enabled(flag_name, u))
        return {
            "total": len(sample_users),
            "enabled": enabled,
            "percentage": round(enabled / len(sample_users) * 100, 1)
        }
```

## 代码演示

```js
class FeatureFlags {
  constructor() {
    this.flags = new Map();
    this.userOverrides = new Map();
  }

  // 注册特性
  register(name, { enabled = false, rollout = 0, description = "" } = {}) {
    this.flags.set(name, { enabled, rollout, description });
  }

  // 判定是否开启
  isEnabled(flagName, userId = "anonymous") {
    // 用户级别的强制开关
    const userOverride = this.userOverrides.get(`${userId}:${flagName}`);
    if (userOverride !== undefined) return userOverride;

    const flag = this.flags.get(flagName);
    if (!flag) return false;
    if (!flag.enabled) return false;

    // 灰度 rollout：用 userId 的 hash 决定是否在范围内
    if (flag.rollout < 100) {
      const hash = this.hash(userId + flagName);
      return hash < flag.rollout;
    }

    return true;
  }

  hash(str) {
    // 简单 hash，返回 0-99 的数
    let h = 0;
    for (let i = 0; i < str.length; i++) {
      h = (Math.imul(31, h) + str.charCodeAt(i)) | 0;
    }
    return Math.abs(h) % 100;
  }

  // 强制开启/关闭（管理员用）
  setOverride(flagName, userId, enabled) {
    this.userOverrides.set(`${userId}:${flagName}`, enabled);
  }

  // 调整灰度比例
  setRollout(flagName, percent) {
    const flag = this.flags.get(flagName);
    if (flag) flag.rollout = percent;
  }

  // 获取所有特性状态
  status(userId) {
    const result = {};
    for (const [name, flag] of this.flags) {
      result[name] = {
        enabled: this.isEnabled(name, userId),
        rollout: flag.rollout,
        description: flag.description,
      };
    }
    return result;
  }
}

// 测试
const flags = new FeatureFlags();
flags.register("newREPL", { enabled: true, rollout: 30, description: "新 REPL 界面" });
flags.register("aiMemory", { enabled: true, rollout: 100, description: "AI 记忆功能" });

const users = ["alice", "bob", "charlie", "david", "alice"];
console.log("特性状态:");
for (const user of users) {
  console.log(`  ${user}: newREPL=${flags.isEnabled("newREPL", user)}, aiMemory=${flags.isEnabled("aiMemory", user)}`);
}
```

## 面试与延伸问题

1. **为什么生产环境推荐用确定性灰度而不是 `random.random()`？** 确定性灰度保证同一用户每次访问结果一致，避免用户刷新页面后功能忽开忽关的体验问题。同时便于调试和复现。
2. **特性开关的存储方案有哪些？** 小型应用用内存（`dict`）；中型应用用 Redis（支持动态修改、跨进程共享）；大型应用用专门的开源方案（如 Unleash、LaunchDarkly）。
3. **如何防止特性开关状态不一致？** 使用单一数据源（如 Redis），所有进程读取同一份数据；修改特性开关时通过消息队列广播变更事件，各进程订阅并更新本地缓存。
4. **灰度比例如何动态调整？** 支持热更新（不改代码不改配置，直接改运行时状态），例如通过管理后台调整 `rollout_percent`，实时生效，不需要重启。
