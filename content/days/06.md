      ## WebFetchTool — 获取网页内容

      WebFetch 是 AI 联网能力的基础。与 BashTool 不同，网页内容通常很大且充满 HTML 标签，直接返回原始 HTML 会浪费上下文窗口。本工具做了几层处理：

      ```python
      async def execute(self, url: str) -> str:
          # 1. URL 验证：只允许 http/https，拒绝 file:// 等危险协议
          if not url.startswith("http"):
              raise ValueError("仅支持 http/https URL")

          # 2. 异步请求：httpx 支持异步 HTTP，比 requests 更适合 Agent
          async with httpx.AsyncClient(timeout=10.0) as client:
              response = await client.get(url, headers={"User-Agent": "..."})

          # 3. 提取 body 并清理标签
          text = self._extract_text(response.text)

          # 4. 长度限制：避免超长内容撑爆上下文窗口
          MAX_LENGTH = 5000
          if len(text) > MAX_LENGTH:
              text = text[:MAX_LENGTH] + f"\n[内容过长，已截断，共 {len(text)} 字符]"
          return text
      ```

      关键设计：
      - **协议白名单**：只允许 `http://` 和 `https://`，拒绝 `file://`（读取本地文件）、`ftp://` 等，防止 AI 利用工具读取内网资源
      - **User-Agent**：很多网站会检查 User-Agent，假装是正常浏览器避免被反爬
      - **HTML 清理**：用正则或 BeautifulSoup 提取正文，去掉 `<script>`、`<style>` 等非内容标签
      - **长度截断**：通常截断到 4000-5000 字符，给 AI 留出推理空间

# Day 6: 让 AI 会搜索网页

## 这一节要解决什么问题？

AI 的知识有截止日期。Claude 的训练数据截止到某一天，那一天之后发生的事情——最新的库版本发布、新闻事件、代码文档更新——AI 一概不知道。更根本的问题是：即使是截止日期之前的内容，AI 的记忆也可能有误差（大模型的"幻觉"问题）。要解决这两个问题，需要让 AI **实时联网**，从网上获取最新、最准确的信息。

本节要建立的核心认知是：**AI 工具系统不只需要"做事的工具"（Bash、FileWrite），还需要"获取信息的工具"（WebSearch、WebFetch）**。信息获取工具让 AI 的知识从"训练时的静态数据"变成"运行时的动态数据"，这是构建真正有用的 AI Agent 的关键一步。

更重要的是，联网工具改变了 AI 的工作模式：以前是"AI 回答问题"，现在是"AI + 工具协作解决问题"。当 AI 发现知识不够用时，它会主动调用 WebSearch 找到相关页面，再用 WebFetch 获取内容，最后综合所有信息给出答案。这种"不知道就查"的能力，是人类使用搜索引擎的方式，也是 AI Agent 应该具备的能力。

## 基础知识

### 1. URL 安全验证

WebFetch 的第一个安全关卡是 **URL 白名单验证**。只允许 `http://` 和 `https://` 协议，拒绝所有其他协议：

```js
function 验证URL(url) {
  try {
    const parsed = new URL(url);
    if (!["http:", "https:"].includes(parsed.protocol)) {
      throw new Error(`不支持的协议: ${parsed.protocol}（只允许 http/https）`);
    }
    return parsed.href; // 返回规范化后的 URL
  } catch (e) {
    throw new Error(`无效的 URL: ${url}`);
  }
}

// 验证样例
验证URL("https://example.com");           // ✓ 通过
验证URL("http://localhost:8080/secret");   // ✓ 通过（但可能是内网）
验证URL("file:///etc/passwd");             // ✗ 拒绝
验证URL("ftp://some-server/data");         // ✗ 拒绝
验证URL("javascript:alert(1)");            // ✗ 拒绝（在 URL 对象层面就被阻止）
```

### 2. HTML 清理：提取纯文本

网页 HTML 充满标签、脚本、样式代码。清理的目标是保留正文，去掉干扰。简单的正则方法适合小工具，正规方案用 DOM 解析库：

```js
// 简单清理：去掉所有 HTML 标签
function 清理HTML(html) {
  // 去掉 <script>、<style>、<head> 等非内容标签及其内容
  let text = html
    .replace(/<script[\s\S]*?<\/script>/gi, "")
    .replace(/<style[\s\S]*?<\/style>/gi, "")
    .replace(/<head>[\s\S]*?<\/head>/gi, "")
    // 去掉所有剩余标签
    .replace(/<[^>]+>/g, " ")
    // 合并多余空白
    .replace(/\s+/g, " ")
    .trim();
  return text;
}

// 更精确：提取 <article> 或 <main> 的内容
// 如果有的话（现代网页通常用这些标签包裹正文）
function 提取正文(html) {
  // 优先找 <main> 标签（正文主要内容）
  const mainMatch = html.match(/<main[^>]*>([\s\S]*?)<\/main>/i);
  const bodyMatch = html.match(/<body[^>]*>([\s\S]*?)<\/body>/i);

  const content = mainMatch ? mainMatch[1] : (bodyMatch ? bodyMatch[1] : html);
  return 清理HTML(content);
}
```

### 3. 搜索结果格式化

搜索工具的输出是给 AI 看的，不是给人类看的。格式要让 AI 快速判断：

- **每个结果的标题** → AI 判断相关性
- **URL** → AI 决定要不要抓取
- **摘要（snippet）** → AI 快速了解内容，不需要抓取就知道大致内容

```js
// 格式化搜索结果
function 格式化搜索结果(results) {
  return results.map((r, i) =>
    `${i + 1}. ${r.title}\n   ${r.url}\n   ${r.snippet}`
  ).join("\n\n");
}

// AI 看到的结果：

//    https://docs.python.org/3.12/whatsnew/3.12.html
```

## 进阶知识

### 同源策略与 CORS

当用 `fetch` 从浏览器直接请求第三方 API 时，会遇到 **CORS（跨域资源共享）** 限制。浏览器要求，只有目标服务器明确允许（通过 `Access-Control-Allow-Origin` 响应头），才能在浏览器环境中跨域请求。

```js
// 从浏览器直接请求 AI API 的问题：
// 如果 AI API 没有返回正确的 CORS 头，浏览器会阻止响应
// 解决方案：
// 1. 后端代理：浏览器 → 自己的后端 → AI API（后端没有 CORS 限制）
// 2. Server-Side Rendering（SSR）：页面在服务器端渲染，不需要前端请求
// 3. JSONP 或 WebSocket（仅适用于特定场景）
```

Claude Code 作为命令行工具（Node.js 环境），没有浏览器的 CORS 限制，可以直接请求任何 API。但如果你的 Agent 要在浏览器前端运行，就要通过后端代理转发请求。

### Robots.txt 与爬虫礼仪

AI Agent 的网络访问也应当遵守爬虫礼仪。`robots.txt` 是网站声明哪些内容允许爬取的约定：

```
# robots.txt 示例 (example.com)
User-agent: *               # 所有爬虫
Disallow: /private/          # 不允许访问 /private 目录
Allow: /public/             # 允许访问 /public 目录

User-agent: GPTBot          # 特别针对 GPT 的爬虫
Disallow: /                 # 完全禁止
```

真实的 AI 产品通常会维护一个域名黑名单（政府网站、银行、医疗记录等），在调用搜索前先检查目标域名是否在黑名单内。

## 代码演示

```js
// 网页读取工具
class WebFetchTool {
  get name() { return "web_fetch"; }
  get description() { return "获取指定 URL 的网页内容"; }

  async execute(url) {
    if (!url.startsWith("http")) {
      throw new Error("URL 必须以 http:// 或 https:// 开头");
    }

    const response = await fetch(url, {
      headers: {
        "User-Agent": "Mozilla/5.0 (compatible; ClaudeCode-Tutorial/1.0)"
      }
    });

    if (!response.ok) {
      throw new Error(`网页获取失败: ${response.status} ${response.statusText}`);
    }

    const text = await response.text();

    // 简化输出（去掉 HTML 标签，只保留正文）
    const bodyMatch = text.match(/<body[^>]*>([\s\S]*?)<\/body>/i);
    const body = bodyMatch ? bodyMatch[1] : text;
    const plainText = body
      .replace(/<[^>]+>/g, " ")
      .replace(/\s+/g, " ")
      .trim();

    return plainText.slice(0, 2000); // 限制长度
  }
}

// 测试
(async () => {
  const tool = new WebFetchTool();
  try {
    // 读取一个简单的网页
    const content = await tool.execute("https://example.com");
    console.log("网页内容（前200字）:", content.slice(0, 200));
  } catch (e) {
    console.error("失败:", e.message);
  }
})();
```
