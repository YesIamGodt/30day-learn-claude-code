      ## 配置迁移系统 — 版本化配置管理

      JS Demo 展示了配置导出/导入的用户界面（JSON 输出、base64 编码、保存到文件），而 Python 源码更深入地解决了**版本迁移**的核心问题：当配置文件从旧版本升级到新版本时，如何让旧配置自动适配新格式。

      ### 版本迁移模式

      `migration.py` 实现了一种经典的版本迁移模式：

      1. **版本注册表**（`MIGRATIONS`）：一个按版本号排序的列表，每个条目是 `(版本号, 迁移函数)`。
      2. **顺序应用**（`sorted(MIGRATIONS)`）：从小版本到大版本依次应用迁移，确保每个升级步骤都正确执行。
      3. **增量更新**：每次迁移只处理相邻两个版本之间的差异，不需要从 0.1 直接跳到 1.0。

      这种设计的好处是**可追溯、可测试**：每个迁移函数都是独立的，可以单独测试；版本路径清晰，如果某个迁移失败，可以精确定位问题。

      ### migrate_config 的执行流程

      ```
      读取 .claude.json（version: "0.1.0"）
              ↓
      MIGRATIONS = [("0.5.0", migrate_to_0.5), ("0.9.0", migrate_to_0.9), ("1.0.0", migrate_to_1.0)]
              ↓
      当前版本 0.1.0 < 0.5.0 → 执行 migrate_to_0.5(config)
              ↓
      当前版本 0.5.0 < 0.9.0 → 执行 migrate_to_0.9(config)
              ↓
      当前版本 0.9.0 < 1.0.0 → 执行 migrate_to_1.0(config)
              ↓
      返回完全迁移后的配置（version: "1.0.0"）
      ```

      ### 扩展：迁移脚本注册

      `register_migration()` 函数允许插件或扩展注册自己的迁移脚本，这是**插件系统**与**迁移系统**结合的典型用法。例如 MCP 插件可以在安装时注册"将 MCP Server 配置从 0.9 格式迁移到 1.0 格式"的脚本。

# Day 25: 配置迁移

## 这一节要解决什么问题？

用户换了电脑，或者重装了系统，所有配置都要重新设置。配置迁移系统：让用户的设置可以导出、导入、跨设备同步。

## 配置迁移流程

```
旧版本配置 (.claude.json)
        ↓
读取当前版本号
        ↓
按顺序应用每个版本的迁移函数
        ↓
新版本配置
        ↓
保存到 .claude.json
```

## 知识进阶：为什么需要版本迁移？

软件升级时，配置文件的结构往往会发生变化：

| 场景 | 旧字段 | 新字段 |
|------|--------|--------|
| 模型改名 | `aiModel` | `model` |
| 单位变化 | `timeout: 30`（秒） | `timeout: { value: 30, unit: "s" }` |
| 拆分类 | `settings: {...}` | `settings: {...}, features: {...}` |

如果不处理迁移，用户升级 Claude Code 后配置就不兼容了：要么报错退出，要么使用错误的默认值。迁移系统让旧配置平滑过渡到新格式。

### Python 真实源码解析

```python
# migration.py — 配置迁移核心实现

from pathlib import Path
import json

# 全局迁移注册表：存储 (版本号, 迁移函数) 元组
# 按版本号顺序排序后依次应用
MIGRATIONS = []

def register_migration(version: str, migration_fn):
    """
    注册一个迁移函数到迁移注册表。
    迁移函数接收旧配置 dict，返回新配置 dict。
    Args:
        version: 目标版本号，迁移后将配置 version 字段更新为此值
        migration_fn: 迁移函数，签名为 (dict) -> dict
    """
    MIGRATIONS.append((version, migration_fn))


def migrate_config(config_path: str = ".claude.json") -> dict:
    """
    加载并迁移配置文件到最新版本。
    如果文件不存在，返回包含默认值的配置。

    迁移流程：
    1. 读取配置文件，获取当前 version
    2. 遍历 MIGRATIONS 注册表，按版本顺序执行迁移
    3. 返回完全迁移后的配置字典
    """
    path = Path(config_path)
    if not path.exists():
        # 配置文件不存在时，返回包含默认值的初始配置
        return {
            "version": "0.1.0",
            "model": "claude-opus-4-5",
            "max_tokens": 4096
        }

    with open(path) as f:
        config = json.load(f)

    # sorted() 按版本号字符串排序（适用于语义化版本号）
    # 依次应用每个版本的迁移函数
    for version, migration_fn in sorted(MIGRATIONS):
        if config.get("version", "0.0.0") < version:
            config = migration_fn(config)
            config["version"] = version  # 更新版本号

    return config
```

from pathlib import Path

# 示例：定义一个具体的迁移函数
def migrate_to_0_5(config: dict) -> dict:
    """从 0.1.0 迁移到 0.5.0"""
    migrated = {**config}
    # 示例：将 timeout 的单位从秒改为毫秒
    if "timeout" in migrated and isinstance(migrated["timeout"], int):
        migrated["timeout_ms"] = migrated["timeout"] * 1000
        del migrated["timeout"]
    return migrated

def migrate_to_0_9(config: dict) -> dict:
    """从 0.5.0 迁移到 0.9.0"""
    migrated = {**config}
    # 新增 features 字段（之前不存在的）
    migrated["features"] = migrated.get("features", {"history": True})
    return migrated

# 注册迁移脚本
register_migration("0.5.0", migrate_to_0_5)
register_migration("0.9.0", migrate_to_0_9)

## 代码演示

```js
const fs = require("fs");
const path = require("path");

class ConfigMigrator {
  constructor() {
    this.version = "1.0";
  }

  // 导出配置
  export(config) {
    const bundle = {
      version: this.version,
      exportedAt: new Date().toISOString(),
      config,
    };

    const json = JSON.stringify(bundle, null, 2);
    const encoded = Buffer.from(json).toString("base64");

    return {
      json,
      encoded,
      file: `cc-config-${Date.now()}.json`,
    };
  }

  // 导入配置
  import(bundle) {
    let data;

    // 支持 JSON 或 base64
    try {
      data = JSON.parse(bundle);
    } catch {
      const decoded = Buffer.from(bundle, "base64").toString("utf-8");
      data = JSON.parse(decoded);
    }

    // 版本兼容性
    if (data.version !== this.version) {
      console.log(`⚠ 配置版本不同 (${data.version} → ${this.version})，尝试迁移...`);
      data.config = this.migrate(data.config, data.version, this.version);
    }

    return data.config;
  }

  // 迁移旧版本配置
  migrate(config, fromVersion, toVersion) {
    const migrated = { ...config };

    // 示例：从 0.9 迁移到 1.0
    if (fromVersion === "0.9" && toVersion === "1.0") {
      // 旧的 model 字段改名了
      if (migrated.aiModel) {
        migrated.model = migrated.aiModel;
        delete migrated.aiModel;
      }
    }

    return migrated;
  }

  // 保存到文件
  saveToFile(config, filePath) {
    const bundle = this.export(config);
    fs.writeFileSync(filePath, bundle.json, "utf-8");
    console.log(`✅ 配置已保存: ${filePath}`);
  }

  // 从文件加载
  loadFromFile(filePath) {
    const content = fs.readFileSync(filePath, "utf-8");
    return this.import(content);
  }
}

// 测试
const migrator = new ConfigMigrator();

const original = {
  apiKey: "sk-xxx",
  model: "claude-sonnet-4-7-20250514",
  maxTokens: 4096,
  theme: "dark",
};

const bundle = migrator.export(original);
console.log("导出 Bundle:", bundle.file);

const imported = migrator.import(bundle.json);
console.log("导入配置:", imported);
```

## 面试与延伸问题

1. **为什么用 `sorted()` 排序而不是按注册顺序执行？** 注册顺序不一定和版本号递增顺序一致。用 `sorted()` 确保无论注册顺序如何，迁移都按版本号从小到大依次执行，保证幂等性。
2. **迁移失败怎么办？** 在 `migrate_config()` 中用 try/except 捕获迁移函数抛出的异常，记录失败原因和状态，然后返回原始配置（而非损坏的配置），并给出清晰的错误提示。
3. **如何支持回滚（降级配置）？** 可以设计双向迁移注册表：`MIGRATIONS_UP` 和 `MIGRATIONS_DOWN`，降级时逆序应用 `MIGRATIONS_DOWN` 中的函数。
4. **配置迁移如何测试？** 为每个迁移函数编写测试用例：用旧版本配置作为输入，验证输出是否符合新版本规范。可以做快照测试（Snapshot Testing）。
