      ## TokenCounter — Token 计数器与成本估算

      TokenCounter 负责追踪每次 API 调用的用量和成本，是 Claude Code 的"账单系统"。它的设计非常简洁：每次 API 调用后，记录输入和输出的 token 数量，然后累计到总成本中。

      ```python
      class TokenCounter:
          def __init__(self):
              self._tokenizer = tiktoken.get_encoding("cl100k_base")
              self.total_input_tokens = 0
              self.total_output_tokens = 0
              self.total_cost = 0.0

          def count(self, text: str) -> int:
              # tiktoken 是 OpenAI 维护的 BPE 分词器，比简单估算精确得多
              return len(self._tokenizer.encode(text))

          def estimate_cost(self, input_tokens, output_tokens, model="claude-sonnet-4-6"):
              prices = PRICING.get(model, PRICING["claude-sonnet-4-6"])
              # 公式：输入token数 × 输入单价 + 输出token数 × 输出单价，再除以 1,000,000
              return (input_tokens * prices["input"] +
                      output_tokens * prices["output"]) / 1_000_000

          def record(self, input_tokens, output_tokens, model="claude-sonnet-4-6"):
              cost = self.estimate_cost(input_tokens, output_tokens, model)
              self.total_input_tokens += input_tokens
              self.total_output_tokens += output_tokens
              self.total_cost += cost

          def summary(self) -> str:
              return (
                  f"Token 使用: 输入 {self.total_input_tokens}，输出 {self.total_output_tokens}\n"
                  f"总成本: ${self.total_cost:.4f}"
              )
      ```

      关键实现细节：

      1. **`tiktoken` 分词器**：`tiktoken`（来自 OpenAI）是目前最精确的 BPE（Byte Pair Encoding）分词器实现。它把文本切分成 token 的方式与 GPT-4 等模型相同。简单估算（"中文按字符数，英文按词数 × 1.3"）误差可能达到 30%，`tiktoken` 的误差在 1-2% 以内。

      2. **`cl100k_base` 编码**：这是 GPT-4 和 Claude 使用的分词器。不同的模型族使用不同的分词器（GPT-2 用 `gpt2`，Claude 用 `cl100k_base`），用错分词器会导致计数偏差。

      3. **累计计量**：`record()` 把每次调用的 token 和成本加到总计，`summary()` 格式化输出。这是生产环境调试和成本控制的基础。

      4. **价格表（PRICING）**：Claude Opus 最贵（$15/$75 每百万），Haiku 最便宜（$0.8/$4 每百万）。同一模型，输入比输出便宜约 5 倍，因为推理成本主要在输出（生成过程更消耗 GPU 资源）。

# Day 9: Token 计费：AI 是怎么算钱的？

## 这一节要解决什么问题？

AI API 不是免费的。每次调用 Claude API，都会消耗一定的 **Token**，而 Token 是按真实货币收费的。理解 Token 计费，是控制 AI 应用成本的第一步——也是理解 AI 能力边界的重要视角。

Token 计费涉及三个核心问题：

**第一，什么是 Token？** AI 不能直接处理文字，它把文字转换成数字（token）来处理。Token 是 AI 处理文本的基本单位，大约等于一个英文单词的四分之三，或者一两个中文字符。理解 Token 的定义，才能理解为什么 AI 的上下文窗口有上限。

**第二，Token 怎么计费？** 输入和输出分别计费，价格不同。输出（AI 生成的文字）比输入（你发送的内容）贵很多，因为 AI 生成内容需要更多 GPU 计算。

**第三，怎么控制成本？** Token 计数不仅用于计费，还能帮助我们优化提示词——如果一个提示词用了 10 万 Token 但其中 5 万是废话，那省掉废话就能直接省钱。了解计数方法，才能做成本优化。

## 概念图解

```
+----------------------------------------------------------+
|                   Token 是什么？                          |
+----------------------------------------------------------+

  英文例子: "Hello, world!"
  切分: ["Hello", ",", " world", "!"]  →  4 tokens

  英文例子: "tokenization" (一个长词)
  切分: ["token", "ization"]           →  2 tokens

  中文例子: "你好，世界"
  切分: ["你", "好", "，", "世", "界"]  →  5 tokens

  ┌─────────────────────────────────────────────────┐
  │  英文: 按空格分隔，词数 × 1.3 ≈ token 数        │

  └─────────────────────────────────────────────────┘
  精确计数: 用 tiktoken / OpenAI tiktoken 库


+----------------------------------------------------------+
|                   Claude API 定价（每百万 Token）         |
+----------------------------------------------------------+

  模型               输入价格($)   输出价格($)   上下文窗口
  ─────────────────────────────────────────────────────
  Claude Opus 4        $15.00       $75.00        200K tokens
  Claude Sonnet 4.6    $3.00       $15.00        200K tokens
  Claude Haiku 4.5     $0.80        $4.00        200K tokens

  计算示例:
  输入 1000 tokens + 输出 500 tokens（使用 Sonnet）
  = (1000/1M × $3) + (500/1M × $15)
  = $0.003 + $0.0075
  = $0.0105 ≈ 1 美分


+----------------------------------------------------------+
|                   成本控制策略                            |
+----------------------------------------------------------+

  1. 历史裁剪（History Trimming）
     当 messages 过长时，裁剪旧消息，只保留最近的上下文
     → 减少输入 token 数，直接省钱

  2. 提示词压缩（Prompt Compression）
     去掉提示词中的废话和冗余描述
     → 减少输入 token 数

  3. 选择合适的模型（Model Selection）
     简单任务用 Haiku，复杂推理用 Opus
     → 差 10 倍价格，但不一定差 10 倍质量

  4. 批量处理（Batch Processing）
     把多个小任务合并成一次 API 调用
     → 减少请求次数（每次请求有固定 overhead）
```

## 基础知识

### 1. Token 计数原理

Token 的本质是 **BPE（Byte Pair Encoding）** 分词算法的产物。分词器扫描文本，找出最常出现的字符对（比如 "th", "er"），把它们合并成子词，重复这个过程，直到词汇表大小合适。这种方法对英文非常高效（常见词整个作为一个 token，长尾词按子词切分）。

```js
// 简单估算（误差较大，适合快速估算）
function 粗估Token数(text) {
  const 英文词数 = text.split(/\s+/).filter(Boolean).length;
  const 中文字符数 = (text.match(/[\u4e00-\u9fa5]/g) || []).length;
  return Math.ceil(英文词数 * 1.3 + 中文字符数);
}

// 精确计数（用 Web Tokenizer API，浏览器环境）
// 注意：浏览器内置的 TextEncoder 不能直接做 BPE，
// 需要引入 polyfill（如 @anthropic-ai/tokenizer）
// 这里用估算演示
console.log(粗估Token数("Hello, world! 你好世界！"));
// 英文: 2 tokens (Hello, world!)
// 中文: 5 tokens (你好世界)
// 总计: ~8 tokens
```

### 3. 价格表与成本计算

```js
const PRICING = {
  "claude-opus-4-5":   { input: 15.0, output: 75.0 },
  "claude-sonnet-4-6": { input: 3.0,  output: 15.0 },
  "claude-haiku-4-5":  { input: 0.8,  output: 4.0  },
};

function 计算成本(inputTokens, outputTokens, model) {
  const price = PRICING[model];
  const inputCost  = (inputTokens  / 1_000_000) * price.input;
  const outputCost = (outputTokens / 1_000_000) * price.output;
  return inputCost + outputCost;
}

// 使用示例
const 本次成本 = 计算成本(1000, 500, "claude-sonnet-4-6");
console.log(`成本: $${本次成本.toFixed(6)}`); // $0.010500
```

## 进阶知识

### tiktoken 的工作原理

`tiktoken` 是 OpenAI 开源的分词器库，Python 版用 Cython 加速，性能极高。核心用法：

```python
import tiktoken

# cl100k_base 编码适用于 GPT-4、Claude、text-embedding-3 等模型
enc = tiktoken.get_encoding("cl100k_base")

tokens = enc.encode("Hello, world! 你好！")
print(len(tokens))  # 打印 token 数量
print(tokens)       # [，运行，调试]

text = enc.decode(tokens)  # 解码回原文
print(text)  # "Hello, world! 你好！"
```

注意：不同模型用不同的编码器。选错了分词器，计数会严重偏差：
- `cl100k_base`：Claude、GPT-4、embedding-3
- `p50k_base`：GPT-3（davinci 系列）
- `r50k_base`：GPT-2

### 上下文窗口与滑动窗口

每个模型都有最大上下文窗口（比如 Sonnet 是 200K tokens）。如果历史消息太长，API 会报错 `629_too_many_tokens`。解决方案：

```python
def 滑动窗口历史(messages: list, max_tokens: int, counter: TokenCounter) -> list:
    """只保留最近、足够装进上下文的 tokens"""
    # 估算：每条消息有固定 overhead（role 字段等），粗略按 1.1 倍计算
    target_tokens = max_tokens - 500  # 留 500 token 给 AI 输出

    # 从最近的消息开始往前数，直到达到 token 上限
    selected = []
    total_tokens = 0
    for msg in reversed(messages):
        msg_tokens = counter.count(msg["content"]) + 50  # +50 是 role 等字段的 overhead
        if total_tokens + msg_tokens > target_tokens:
            break
        selected.insert(0, msg)  # 头部插入，保持顺序
        total_tokens += msg_tokens

    return selected
```

## 代码演示

```js
// 简单 Token 计数（粗略估计）
function 估算Token数(text) {
  // 英文：按空格分割，粗略估算
  const 英文词数 = text.split(/\s+/).length;
  // 中文：按字符数估算
  const 中文字符数 = (text.match(/[\u4e00-\u9fa5]/g) || []).length;
  const 英文Token = Math.ceil(英文词数 * 1.3); // 每词约 1.3 token
  const 中文Token = 中文字符数; // 每中文字约 1 token
  return Math.ceil(英文Token + 中文Token);
}

// Anthropic 定价
const PRICING = {
  "claude-sonnet-4-7-20250514": { input: 3, output: 15 }, // $/百万token
};

function 计算成本(inputText, outputText, model) {
  const inputTokens = 估算Token数(inputText);
  const outputTokens = 估算Token数(outputText);
  const pricing = PRICING[model];

  const inputCost = (inputTokens / 1_000_000) * pricing.input;
  const outputCost = (outputTokens / 1_000_000) * pricing.output;

  return {
    inputTokens,
    outputTokens,
    totalTokens: inputTokens + outputTokens,
    inputCost: inputCost.toFixed(6),
    outputCost: outputCost.toFixed(6),
    totalCost: (inputCost + outputCost).toFixed(6),
  };
}

// 测试
const result = 计算成本(
  "请用 Python 写一个快速排序",
  "def quick_sort(arr): ...",
  "claude-sonnet-4-7-20250514"
);

console.log("Token 使用报告:");
console.log(`  输入: ${result.inputTokens} tokens ($${result.inputCost})`);
console.log(`  输出: ${result.outputTokens} tokens ($${result.outputCost})`);
console.log(`  总计: ${result.totalTokens} tokens ($${result.totalCost})`);
```
