      ## PluginManager — 动态插件加载系统

      JS Demo 展示了插件系统的"外观"（Plugin 基类、Hook 机制、插件注册/卸载），而 Python 源码展示了真正能在生产环境中使用的**动态模块加载**机制，使用 Python 标准库的 `importlib`。

      ### 插件加载的三步走

      `load_plugin()` 实现了完整的动态加载流程：

      1. **检查文件存在**：`path.exists()` 确认 `.claude/plugins/{name}.py` 文件存在
      2. **创建模块规格**：`spec_from_file_location(name, path)` 创建模块加载规格（Module Spec）
      3. **加载执行**：
         - `module_from_spec(spec)` 创建空模块对象
         - `sys.modules[name] = module` 注册到 sys.modules（防止重复加载）
         - `spec.loader.exec_module(module)` 执行模块代码（这会触发模块中的 `register()` 等调用）
      4. **保存引用**：`self._plugins[name] = module` 保持对模块的引用，防止被 GC 回收

      ### 插件卸载的必要性

      `unload_plugin()` 必须同时做两件事：
      - 从 `self._plugins` 删除引用（让 Python GC 可以回收模块对象）
      - 从 `sys.modules` 删除条目（否则下次加载同名模块会命中缓存，不会重新执行）

      如果只做一件，插件代码会残留：例如插件注册了一个定时任务，只删引用不删 sys.modules，下次加载同名插件时旧的定时任务还在运行。

      ### 插件系统的安全性

      当前实现有几个安全风险需要注意：

      1. **代码注入**：插件路径来自用户输入（`name` 参数），需要验证路径合法性，防止 `../../../etc/passwd` 路径遍历
      2. **沙箱缺失**：插件代码在主进程执行，可以访问所有 Python 能力，需要考虑 `seccomp` 或子进程隔离
      3. **版本兼容**：插件可能依赖特定版本的 Claude Code API，需要版本检查机制

      ### 真实插件示例结构

          """插件入口：Claude Code 加载插件时会调用此函数"""

# Day 27: 插件系统

## 这一节要解决什么问题？

别人想给你的 Claude Code 加新功能，但不想改你的代码。插件系统：定义好接口规范，第三方就能往里塞东西，不需要动核心代码。

## 插件架构

```
核心系统
  ↓ 定义接口
Plugin API（钩子、事件、数据格式）
  ↓
第三方插件（搜索增强 / 翻译 / 代码美化 / ...）
```

## 知识进阶：插件系统的核心价值

插件系统的本质是**控制反转（IoC）**：核心系统定义扩展点，插件在扩展点上注册自己的逻辑，运行时由核心系统调用插件代码。

这与 Skill 系统（Day 21）的区别在于：
- **Skill**：定义"AI 怎么思考"（提示词模板）
- **Plugin**：定义"AI 能做什么"（真实的功能扩展）

### Python 真实源码解析

```python
# plugins.py — 插件动态加载核心实现

from pathlib import Path
from importlib.util import spec_from_file_location, module_from_spec
import sys

class PluginManager:
    """
    插件管理器：负责动态加载和卸载 Python 插件模块。
    插件是标准的 Python 模块（.py 文件），放在 .claude/plugins/ 目录下。
    """

    def __init__(self, plugin_dir: str = ".claude/plugins"):
        self.plugin_dir = Path(plugin_dir)
        self._plugins: dict = {}

    def load_plugin(self, name: str) -> bool:
        """
        动态加载插件模块。
        加载流程：
        1. 检查插件文件是否存在（plugin_dir/name.py）
        2. 创建模块规格（Module Spec）—— 告诉 Python 如何加载这个模块
        3. 创建空模块对象并注册到 sys.modules
        4. 执行模块代码（exec_module 触发模块顶层代码）
        5. 保存模块引用，防止被 GC 回收
        """
        path = self.plugin_dir / f"{name}.py"
        if not path.exists():
            return False

        # spec_from_file_location：用文件路径创建模块规格
        spec = spec_from_file_location(name, path)
        module = module_from_spec(spec)

        # 在 sys.modules 中注册（必须！否则重复加载会走缓存）
        sys.modules[name] = module

        # 执行模块代码，这会触发模块中的注册逻辑
        spec.loader.exec_module(module)
        self._plugins[name] = module
        return True

    def unload_plugin(self, name: str):
        """
        卸载插件：同时清理两个地方。
        - self._plugins：移除管理器对模块的引用
        - sys.modules：移除 Python 的模块缓存
          必须两者都删，否则：
          1. 只删 _plugins → 模块对象被 GC，但 sys.modules 缓存还在
          2. 只删 sys.modules → 下次加载同名插件会重新执行旧代码
        """
        if name in self._plugins:
            del self._plugins[name]
        if name in sys.modules:
            del sys.modules[name]

    def list_plugins(self) -> list[str]:
        """返回已加载插件的名称列表"""
        return list(self._plugins.keys())
```

### 进阶：钩子（Hook）机制

```python
# 进阶：为 PluginManager 增加钩子机制
class HookablePluginManager(PluginManager):
    def __init__(self, *args, **kwargs):
        super().__init__(*args, **kwargs)
        self._hooks: dict[str, list[callable]] = {}

    def register_hook(self, event: str, handler: callable):
        """注册事件钩子：event 触发时调用 handler"""
        if event not in self._hooks:
            self._hooks[event] = []
        self._hooks[event].append(handler)

    async def trigger_hook(self, event: str, *args, **kwargs):
        """触发事件钩子：依次调用所有注册的 handler"""
        handlers = self._hooks.get(event, [])
        results = []
        for handler in handlers:
            result = handler(*args, **kwargs)
            if asyncio.iscoroutine(result):
                result = await result
            results.append(result)
        return results
```

### 快速参考表

| 方法/步骤 | 作用 | 关键点 |
|----------|------|--------|
| `spec_from_file_location()` | 创建模块加载规格 | Python 标准库 |
| `module_from_spec()` | 创建空模块对象 | 尚未执行代码 |
| `sys.modules[name] = module` | 注册模块到全局缓存 | 防止重复加载 |
| `spec.loader.exec_module()` | 执行模块代码 | 触发 register() |
| `unload_plugin()` | 卸载插件 | 必须清两处缓存 |

## 代码演示

```js
// 插件接口规范
class Plugin {
  get name() { throw new Error("必须提供 name"); }
  get version() { return "1.0.0"; }
  onLoad?(registry) {}    // 加载时调用
  onUnload?() {}          // 卸载时调用
}

// 插件管理器
class PluginManager {
  constructor() {
    this.plugins = new Map();
    this.tools = new Map();
    this.hooks = new Map();
  }

  // 注册插件
  register(plugin) {
    if (this.plugins.has(plugin.name)) {
      throw new Error(`插件已存在: ${plugin.name}`);
    }

    plugin.onLoad?.(this);
    this.plugins.set(plugin.name, plugin);
    console.log(`✅ 加载插件: ${plugin.name} v${plugin.version}`);
  }

  // 卸载插件
  unload(name) {
    const plugin = this.plugins.get(name);
    if (!plugin) return;

    plugin.onUnload?.();
    this.plugins.delete(name);
    console.log(`🗑 卸载插件: ${name}`);
  }

  // 注册钩子
  registerHook(name, fn) {
    if (!this.hooks.has(name)) this.hooks.set(name, []);
    this.hooks.get(name).push(fn);
  }

  // 触发钩子
  async triggerHook(name, ...args) {
    const funcs = this.hooks.get(name) ?? [];
    let result;
    for (const fn of funcs) {
      result = await fn(...args);
    }
    return result;
  }

  list() {
    return Array.from(this.plugins.values()).map(p => ({
      name: p.name,
      version: p.version,
    }));
  }
}

// 示例插件：自动翻译
class TranslatePlugin extends Plugin {
  get name() { return "translate"; }
  get version() { return "1.0.0"; }

  onLoad(registry) {
    registry.registerHook("beforeResponse", async (response) => {
      return `[翻译插件增强] ${response}`;
    });
  }
}

// 使用
const manager = new PluginManager();
manager.register(new TranslatePlugin());
console.log("已加载插件:", manager.list());
```

## 面试与延伸问题

1. **Python 的 `importlib` 和 `__import__` 有什么区别？** `__import__` 是底层内置函数，API 较原始；`importlib` 是更现代的模块，提供 `import_module()`、`spec_from_file_location()` 等高级函数，代码更清晰，更推荐使用。
2. **插件隔离：如何防止恶意插件影响主进程？** 可以用子进程（`multiprocessing.Process`）运行插件，主进程通过 IPC（管道/消息队列）与插件通信；或者用 `__slots__` 限制插件能访问的属性。
3. **插件版本兼容性如何保证？** 在插件的 `__init__.py` 或入口函数中检查 Claude Code 版本，例如 `if __claude_version__ < "1.5.0": raise ImportError("需要 Claude Code 1.5.0+")`。
4. **热重载：如何做到插件更新后不重启就生效？** 监视插件文件的修改时间（`mtime`），检测到变化时调用 `unload_plugin()` 清理旧模块，再调用 `load_plugin()` 重新加载。需要注意卸载钩子（`onUnload`）要清理定时任务等资源。
