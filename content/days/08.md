      ## QueryEngine — 工具调用循环引擎

      `QueryEngine` 是 Claude Code 的"大脑"，负责协调 AI 模型和工具之间的来回交互。它实现了一个 **ReAct 循环**（Reason + Act）：让 AI 思考 → 根据思考结果决定是否调用工具 → 执行工具 → 把结果返回给 AI → AI 再思考 → ……直到 AI 认为任务完成。

      ```python
      class QueryEngine:
          def __init__(self, client, history, max_turns=30):
              self.client = client
              self.history = history
              self.max_turns = max_turns

          async def run(self, prompt: str) -> str:
              for turn in range(self.max_turns):
                  response, tool_calls = await self.step(prompt)
                  prompt = ""  # 第一次之后的 prompt 为空，因为已加入历史

                  if not tool_calls:  # AI 说"我完成回复了"
                      return response.content[0].text

                  for tc in tool_calls:
                      result = await self.execute_tool(tc)
                      # 工具结果以 user 消息追加，让 AI 继续思考
                      self.history.add_message("user",
                          f"[TOOL_CALL id=\"{tc.id}\"] {tc.name} result: {result.output}"
                      )

              return "错误: 达到最大循环次数"

          async def step(self, prompt: str) -> tuple:
              if prompt:
                  self.history.add_message("user", prompt)

              tools = [t.to_schema() for t in get_registry().list_tools()]

              response = self.client.messages.create(
                  model="claude-opus-4-5",
                  messages=self.history.get_messages(),
                  tools=tools,
              )

              text = ""
              if response.content and hasattr(response.content[0], 'text'):
                  text = response.content[0].text
              if text:
                  self.history.add_message("assistant", text)

              return response, response.tool_calls or []
      ```

      几个核心细节：

      1. **`max_turns` 防止无限循环**：AI 可能陷入"工具 A 调用工具 B，工具 B 又调用工具 A"的死循环。`max_turns` 限制了最大循环次数，超过后强制退出并报错。

      2. **`tool_calls or []`**：Anthropic API 返回的 `response.tool_calls` 可能是 `None`（AI 不调用工具时），用 `or []` 提供空列表默认值，避免解包错误。

      3. **`prompt = ""` 的意义**：第一次调用 `run("帮我看看文件")` 时，`step` 会把 `prompt` 加入历史。但后续循环中，历史已经包含了之前的消息，不需要再次添加用户 prompt（否则会导致重复）。

      4. **响应提取的防御性写法**：`if response.content and hasattr(response.content[0], 'text')` —— Anthropic API 的 content 可能有不同类型（text、tool_use 等），只有 text 类型才有 `.text` 属性，其他情况要安全处理。

      5. **异常包装**：`execute_tool` 把所有异常统一包装成 `ToolResult(is_error=True)`，保证循环不会因为单个工具失败而崩溃。

# Day 8: 工具调用循环：AI 怎么做决策？

## 这一节要解决什么问题？

前几节我们有了工具系统、对话历史、API 调用能力，但还缺少一个核心组件：**把这些串起来形成"循环"的引擎**。AI 不是一次调用就完成任务的。典型的 AI Agent 工作流程是这样的：

1. 用户说："帮我把 `src/app.py` 里的所有 `print` 改成 `logger.info`"
2. AI 思考：我需要先看看 `src/app.py` 的内容 → 调用 `file_read` 工具
3. 工具返回文件内容
4. AI 看到内容后：好，我来做修改 → 调用 `file_write` 工具
5. 工具返回"写入成功"
6. AI 说："已完成修改，共改了 5 处"
7. 完成！

这个 **"思考 → 行动 → 观察 → 再思考"** 的循环叫做 **ReAct**（Reason + Act），是 AI Agent 的核心执行范式。`QueryEngine` 就是实现这个循环的代码。

理解 ReAct 循环，也能帮助你理解为什么 AI Agent 会出现"卡在某个工具里出不来"或"重复调用同一个工具"的问题——这些问题的根源都在循环逻辑里，而非 AI 的"智能"不足。

## 概念图解

```
+----------------------------------------------------------+
|                  ReAct 循环完整流程                        |
+----------------------------------------------------------+

  ┌──────────────────────────────────────────────────────┐
  │                    QueryEngine.run()                 │
  │                                                      │
  │  ┌─────────────────┐                                 │

  │  │       "[TOOL_CALL] file_read result: 文件内容") │
  │  └─────────────────┘                                 │
  │                     ↓ 无 tool_calls → 结束          │

  │  │  Turn 2         │                                 │

  │  │     → AI 看到文件内容，知道怎么改了               │
  │  │     → stop_reason: "tool_use"                   │
  │  │  2. tool_calls: [ { name: "file_write", ... } ] │

  │                     ↓ 无 tool_calls → 结束          │
  │  ┌─────────────────┐                                 │
  │  │  Turn 3         │                                 │
  │  │  1. client.messages.create(...)                   │
  │  │     → AI 看到写入成功                             │
  │  │     → stop_reason: "end_turn"（最终回复）        │
  │  │     → text: "已完成修改，共改了 5 处"           │
  │  └─────────────────┘                                 │
  │                     ↓ 遇到 tool_use?                 │
  │                     ↓ 有 tool_calls?                 │
  │                     ↓ reach max_turns?               │
  │                                                      │
  │  返回最终文字给用户                                    │
  └──────────────────────────────────────────────────────┘


+----------------------------------------------------------+
|              stop_reason：AI 停止的原因                   |
+----------------------------------------------------------+

  "end_turn":       AI 认为任务完成，返回最终文字给用户
  "tool_use":       AI 决定调用工具，返回 tool_calls 列表
  "max_tokens":     输出 token 达到上限（被截断）
  "stop_sequence":  遇到停止序列（比如开发者指定的结束标记）
```

## 基础知识

### 1. stop_reason：AI 停止的"原因码"

每次 API 调用返回时，`stop_reason` 告诉程序 AI 为什么停止。两种主要情况：

```js
const response = await client.messages.create({
  model: "claude-sonnet-4-7-20250514",
  messages: history.getMessages(),
  tools: registry.list().map(t => t.toSchema()),
});

// 情况 1：AI 决定调用工具
if (response.stop_reason === "tool_use") {
  const toolCalls = response.content; // 工具调用列表
  for (const toolCall of toolCalls) {
    const tool = registry.get(toolCall.name);
    const result = await tool.execute(toolCall.input);
    // 把结果加回历史，继续循环
    history.addMessage("user", `[TOOL_CALL] ${tool.name} result: ${result}`);
  }
}

// 情况 2：AI 给出了最终回复
if (response.stop_reason === "end_turn") {
  const finalText = response.content[0].text;
  console.log("AI:", finalText); // 打印给用户
}
```

### 2. 工具调用的结构

Anthropic API 返回的 tool_call 结构如下：

```js
// AI 返回的工具调用
{
  id: "toolu_01A2B3C4D5",       // 唯一 ID，用于标识这次调用
  name: "file_read",             // 工具名称（与 registry 中的一致）
  input: {
    path: "src/app.py"           // 工具的参数（由工具的 input_schema 定义）
  }
}
```

### 3. 循环终止条件

ReAct 循环在以下任一条件满足时终止：

```js
async function run(userPrompt) {
  for (let turn = 0; turn < MAX_TURNS; turn++) {
    // 发送请求
    const response = await sendToAI(history, tools);

    // 条件 1：AI 说"完成了"（end_turn）
    if (response.stop_reason === "end_turn") {
      return response.content[0].text;
    }

    // 条件 2：超过最大循环次数（防止死循环）
    if (turn === MAX_TURNS - 1) {
      return "执行超时（已达到最大循环次数），请重试";
    }

    // 执行所有工具调用
    for (const toolCall of response.content) {
      const result = await executeTool(toolCall);
      history.addMessage("user", `[TOOL_CALL] result: ${result}`);
    }
  }
}
```

## 进阶知识

### 并行工具调用

如果 AI 一次返回多个工具调用（比如"先看看 `src/a.py` 和 `src/b.py`"），理论上可以并行执行以节省时间：

```js
// 串行：等一个完成再执行下一个
for (const toolCall of toolCalls) {
  const result = await executeTool(toolCall); // 阻塞
}

// 并行：用 Promise.all 同时执行
const results = await Promise.all(
  toolCalls.map(tc => executeTool(tc))
);
// results 数组的顺序与 toolCalls 一致，可以直接对应
```

但需要注意：**并行执行时，如果两个工具修改同一个文件，可能产生竞态条件**。比如 AI 同时调用两个 `file_write` 写同一个文件，最后哪个结果会被 AI 看到是不确定的。所以 Claude Code 通常按顺序执行。

### 多轮对话中的 ReAct

ReAct 循环不仅适用于单次任务，也适用于多轮对话。当用户说"现在把日志级别改成 DEBUG"时，AI 会：
1. 先调用 file_read 确认当前配置
2. 分析配置格式
3. 调用 file_write 修改
4. 调用 bash 执行 `grep -r "DEBUG" .` 验证

每次人类回复都可能触发新的 ReAct 循环，循环之间通过 `ConversationHistory` 保持上下文连贯。

## 代码演示

```js
class QueryEngine {
  constructor(client, history, registry) {
    this.client = client;
    this.history = history;
    this.registry = registry;
    this.maxIterations = 10;
  }

  async run(userInput) {
    this.history.addUser(userInput);

    for (let i = 0; i < this.maxIterations; i++) {
      // 1. 让 AI 思考并决定是否调用工具
      const response = await this.client.messages.create({
        model: "claude-sonnet-4-7-20250514",
        max_tokens: 1024,
        messages: this.history.getMessages(),
        tools: this.registry.list().map(t => t.toSchema()),
      });

      const stopReason = response.stopReason;
      const content = response.content[0];

      // 2. 如果是最终回复，直接返回
      if (stopReason === "end_turn") {
        const text = content.text;
        this.history.addAssistant(text);
        return text;
      }

      // 3. 如果是工具调用，执行它
      if (stopReason === "tool_use") {
        const toolName = content.name;
        const toolInput = content.input;

        console.log(`→ 调用工具: ${toolName}`);
        const tool = this.registry.get(toolName);
        const result = await tool.execute(toolInput);

        // 4. 把工具结果加回历史，让 AI 继续思考
        this.history.addAssistant(
          JSON.stringify({ type: "tool_result", name: toolName, content: result })
        );
        continue;
      }
    }

    return "执行超时，请重试。";
  }
}

console.log("QueryEngine 架构演示完成。");
console.log("实际运行需要真实的 API Key。");
```

## 知识点速查表

| 概念 | 说明 | 示例 |
|------|------|------|
| ReAct 循环 | Reason（推理）+ Act（行动）循环 | AI 思考 → 工具调用 → 看结果 → 再思考 |
| stop_reason | AI 停止的原因码 | `"end_turn"`, `"tool_use"` |
| 工具调用列表 | AI 返回的待执行工具 | `[{ id, name, input }]` |
| 循环终止条件 | 无工具调用 / 达到上限 | `if (!tool_calls) break` |
| max_turns | 最大循环次数，防止死循环 | 设为 30，超过则退出 |
| 工具结果转 user 消息 | 让 AI 看到工具输出 | `[TOOL_CALL] bash result: ...` |
| 并行 vs 串行执行 | 多个工具可并行，但要考虑竞态条件 | `Promise.all([...])` |
| 上下文连贯 | 循环之间通过 history 保持记忆 | 工具结果追加到 messages |

## 面试题

**Q1: `max_turns` 限制了最大循环次数，但如果 AI 每次都做很小的进展（比如每次只读一个文件的一行），30 次循环也不足以完成任务，你如何改进这个策略？**

提示：考虑"进度检测"——如果连续两次循环 AI 调用的工具和参数完全相同，说明它陷入了循环。另外可以用 token 计数而非轮次计数。

**Q2: 假设 AI 同时返回了两个工具调用：`bash("rm -rf /tmp/cache")` 和 `file_write(...)`，你的程序应该并行执行还是串行？为什么？考虑文件依赖、错误处理和安全审计。**
