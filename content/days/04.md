      ## BaseTool — 工具的抽象基类

      所有工具都继承自 `BaseTool`，这是一个 Python 的**抽象基类**（Abstract Base Class, ABC）。`ABC` 是 Python 内置模块，用于强制子类必须实现某些方法——如果忘记实现 `name` 或 `execute`，Python 会在实例化时直接报错，而不是等到运行时才发现缺失。

      ```python
      from abc import ABC, abstractmethod

      class BaseTool(ABC, Generic[TInput, TOutput]):
          """所有工具的抽象基类"""

          @property
          @abstractmethod
          def name(self) -> str:
              """工具的唯一名称（必须实现）"""
              ...

          @abstractmethod
          async def execute(self, input_data: TInput) -> TOutput:
              """执行工具的核心逻辑（必须实现，且是异步的）"""
              ...
      ```

      `Generic[TInput, TOutput]` 是 Python 的**泛型**语法，声明这个工具接受什么类型的输入、返回什么类型的输出——`BashTool[str, str]` 表示输入和输出都是字符串；`FileReadTool[str, str]` 同理，但也可以设计成 `FileReadTool[str, bytes]` 表示返回字节流。泛型让类型提示更精确，帮助 IDE 提供自动补全，也方便静态分析工具检查类型安全。

      `to_schema()` 方法将工具转换为 JSON Schema 格式，这是 Anthropic API 要求的工具定义格式。AI 模型通过这个 schema 理解每个工具是做什么的、接受什么参数。

  - path: tools/registry.py
    title: ToolRegistry 工具注册表
    explainer: |
      ## ToolRegistry — 全局工具注册中心

      `ToolRegistry` 是整个工具系统的"电话簿"：工具通过 `register()` 登记进来，通过 `get(name)` 按名字查找。没有注册表，AI 就不知道有哪些工具可用，更不知道该调用哪个。

      ```python
      class ToolRegistry:
          def __init__(self):
              self._tools: dict[str, BaseTool] = {}  # 字典，键=工具名，值=工具实例

          def register(self, tool: BaseTool) -> None:
              if tool.name in self._tools:
                  raise ValueError(f"工具 {tool.name} 已注册")  # 防重复注册
              self._tools[tool.name] = tool

          def get(self, name: str) -> BaseTool:
              if name not in self._tools:
                  raise KeyError(f"工具 {name} 未注册")  # 防查空
              return self._tools[name]
      ```

      关键设计决策：
      - **单例全局注册表**：模块级变量 `_registry = ToolRegistry()`，通过 `get_registry()` 访问，保证整个程序只有一份注册表实例
      - **防重复注册**：如果两次注册同名工具，直接抛异常而不是静默覆盖（覆盖会导致难以调试的问题）
      - **`clear()` 方法**：清空注册表，这在测试或重启 Agent 时非常有用——可以重新初始化一套工具

      这个模式和 Web 开发中的"依赖注入容器"（Dependency Injection Container）完全一致，是解耦设计的经典范式。

# Day 4: 工具箱设计：怎么管 40 个工具？

## 这一节要解决什么问题？

Claude Code 有 40+ 工具：Bash 执行命令、读写文件、搜索网页、读图片、执行 Python 代码、搜索代码库……这么多工具，怎么管理？如果每个工具的调用方式都不一样，AI 核心代码就要写无数个 `if tool_name == "bash": run_bash()`——既不优雅，也无法扩展。

解决方案是**统一的"工具箱"接口**。就像宜家的工具箱，不管里面装的是螺丝刀、锤子还是钳子，外壳都一样：有一个把手、能打开、能放回去。Claude Code 的每个工具也有统一的外壳：`name`（叫什么）、`description`（做什么用）、`execute()`（怎么执行）。**有了这个统一接口，AI 只需要按名字调用工具，工具内部怎么实现的，AI 核心完全不关心。**

这背后是一个经典的设计模式：**插件式架构**（Plugin Architecture）。想象一个摄影 App，滤镜是"插件"——App 本身不知道会有多少种滤镜，只需要定义"输入图片，输出处理后的图片"这个接口，任何人按接口实现一个滤镜，App 就能加载使用。Claude Code 的工具系统就是这个模式：工具开发者只需继承 `BaseTool`，实现三个方法，然后调用 `registry.register(my_tool)`，工具就立刻能被 AI 调用。**不需要修改 AI 核心一行代码。**

理解这个设计，也能帮助理解为什么 Claude Code 能不断新增功能——新功能以"工具"为单位接入，接入成本极低，这是现代 AI 应用的主流架构。

## 基础知识

### 1. 工具的统一接口

无论工具做什么，都遵守同一个接口。这不仅让 AI 核心代码简洁，也让工具开发者有清晰的规范可循：

```js
// 工具的通用接口（JS 里用约定代替抽象基类）
// 每个工具都要有：name、description、execute()

class BaseTool {
  get name() { throw new Error("子类必须实现 name"); }
  get description() { throw new Error("子类必须实现 description"); }
  async execute(input) { throw new Error("子类必须实现 execute"); }

  // 转换为 AI API 能理解的 schema
  toSchema() {
    return {
      name: this.name,
      description: this.description,
      // input_schema 由子类提供，描述参数类型
      input_schema: this.inputSchema || { type: "object" },
    };
  }
}

// 示例：HelloTool
class HelloTool extends BaseTool {
  get name() { return "hello"; }
  get description() { return "返回问候语"; }
  get inputSchema() {
    return { type: "object", properties: { name: { type: "string" } } };
  }
  async execute(input) {
    return `Hello, ${input.name || "World"}!`;
  }
}
```

### 2. 注册表模式：注册和查找

注册表负责两件事：**添加工具**（register）和**按名查找**（get）。它的实现就是一个简单的 `Map<string, Tool>`：

```js
class ToolRegistry {
  constructor() {
    this._tools = new Map();  // 工具名 → 工具实例
  }

  // 注册：把工具加入注册表
  register(tool) {
    if (this._tools.has(tool.name)) {
      throw new Error(`工具 ${tool.name} 已注册`); // 防止重复
    }
    this._tools.set(tool.name, tool);
  }

  // 获取：给定名字，找到对应工具
  get(name) {
    const tool = this._tools.get(name);
    if (!tool) {
      throw new Error(`工具 ${name} 未注册`); // 找不到就报错
    }
    return tool;
  }

  // 列表：返回所有已注册工具
  list() {
    return Array.from(this._tools.values());
  }

  // 清空：测试或重启时用
  clear() {
    this._tools.clear();
  }
}
```

### 3. 工具的 schema 转换

AI 模型不知道 Python class 是什么，它只认识 JSON。所以工具需要提供一个 **JSON Schema**，描述工具叫什么、做什么、接受什么参数：

```js
// BashTool 的 schema（JSON 格式，AI 能理解）
{
  name: "bash",
  description: "执行 shell 命令，返回 stdout 和 stderr 的组合输出",
  // input_schema 告诉 AI：这个工具只接受一个参数 command，类型是字符串
  input_schema: {
    type: "object",
    properties: {
      command: { type: "string", description: "要执行的 shell 命令" }
    },
    required: ["command"]
  }
}
```

## 进阶知识

### 泛型约束：让类型提示更精确

Python 的 `Generic[TInput, TOutput]` 泛型让每个工具声明自己输入输出的类型：

```python
# BashTool：输入是 str（命令字符串），输出是 str（结果字符串）
class BashTool(BaseTool[str, str]):
    ...

# FileReadTool：输入是 str（文件路径），输出是 str（文件内容）
class FileReadTool(BaseTool[str, str]):
    ...

# WebSearchTool：输入是 str（查询词），输出是 str（搜索结果摘要）
class WebSearchTool(BaseTool[str, str]):
    ...
```

这样做的好处是：IDE 知道 `BashTool.execute()` 返回字符串，可以做类型检查和自动补全。大型团队里，这种类型约束能显著减少 bug。

### 工具依赖注入：灵活组合

真正的 Agent 可能会根据不同场景加载不同的工具集。注册表支持按需加载：

```python
# 只加载文件操作相关的工具（用于纯文件处理场景）
registry = ToolRegistry()
registry.register(FileReadTool())
registry.register(FileWriteTool())

# 加载全部工具（完整 Claude Code）
registry_full = ToolRegistry()
for tool in all_tools:
    registry_full.register(tool)
```

## 代码演示

```js
// 工具的通用接口（JS 里用约定代替抽象基类）
// 每个工具都要有：name、description、execute()

class BaseTool {
  get name() { throw new Error("子类必须实现 name"); }
  get description() { throw new Error("子类必须实现 description"); }
  async execute(input) { throw new Error("子类必须实现 execute"); }
}

// 工具箱（注册表）
class ToolRegistry {
  constructor() {
    this._tools = new Map();
  }

  // 注册工具
  register(tool) {
    if (this._tools.has(tool.name)) {
      throw new Error(`工具 ${tool.name} 已注册`);
    }
    this._tools.set(tool.name, tool);
  }

  // 获取工具
  get(name) {
    if (!this._tools.has(name)) {
      throw new Error(`工具 ${name} 未注册`);
    }
    return this._tools.get(name);
  }

  // 列出所有工具
  list() {
    return Array.from(this._tools.values());
  }
}

// 创建一个具体工具
class HelloTool extends BaseTool {
  get name() { return "hello"; }
  get description() { return "返回问候语"; }
  async execute(input) {
    return `Hello, ${input}!`;
  }
}

// 使用
const registry = new ToolRegistry();
registry.register(new HelloTool());

console.log("已注册工具:", registry.list().map(t => t.name));
const result = await registry.get("hello").execute("Claude");
console.log("执行结果:", result);
```

## 知识点速查表

| 概念 | 说明 | 示例 |
|------|------|------|
| 统一接口 | 所有工具都有 name、description、execute() | `BashTool`、`FileReadTool` 都一样 |

## 面试题

**Q1: 如果 AI 同时返回了两个工具调用请求（比如让 bash 执行命令，同时还要读写文件），你的程序应该并行执行还是串行？为什么？**

提示：考虑工具之间的关系。如果两个工具完全独立（比如 bash 和 file_read），并行执行能节省时间。但如果第二个工具的输入依赖第一个的输出（比如先 grep 再 wc），就必须串行。

**Q2: `registry.register(tool)` 时，如果传入的工具 name 与已有工具重名，当前的实现是抛异常。你觉得这个设计合理吗？还是应该静默覆盖？为什么？**

提示：思考"静默覆盖"会导致什么问题。在 Claude Code 的场景下，如果同一个名字指向了不同的实现，会发生什么？
