      ## PermissionSystem — 危险命令检测

      权限系统是 Claude Code 的"安全门卫"。当 AI 决定要执行一条命令时，PermissionSystem 会在命令真正运行之前，对它做一轮安检。

      **检测策略分为三层**：

      1. **自动放行（Always Allow）**：像 `echo`、`pwd`、`ls`、`cat` 这些只读命令，几乎不可能造成破坏，直接放行，用户体验不受影响。

# Day 11: 权限安全：什么能做，什么不能？

## 这一节要解决什么问题？

当你把一个 AI 接入 shell，它就拥有了执行任意命令的能力。这带来巨大价值的同时，也带来了巨大风险。想象一下，用户让 AI "清理一下 tmp 目录"，AI 兴冲冲地执行了 `rm -rf /tmp`，但如果权限设置不当，这条命令可能带走整个文件系统——这不是 AI 的"恶意"，而是边界没画好。

AI 执行命令前，我们需要一道**安全门**，来区分：

- **无害命令**：查看文件、查看目录结构、查看进程
- **有风险命令**：写入文件、执行脚本、下载内容
- **危险命令**：`rm -rf`、`dd`、`>` 重定向到系统文件

权限系统（Permission Guard）就是在 AI 和真实系统之间画一条安全线。它让 AI 执行每条命令前都经过检查——要么直接放行，要么弹出警告，要么直接拒绝。

但权限控制不是"要么全开要么全关"这么简单。太严格会让 AI 变得迟钝，太宽松又形同虚设。好的权限系统需要**分级**、**可配置**、**可审计**。

## 概念图解

```
用户输入: "帮我看看项目里有多少行代码"

```

## 基础知识

### 权限分级设计

最直觉的权限模型是**级别数值比较**。定义几个离散级别，用数字表示强度：

```js
// 权限级别：数字越大，可做的事越多
const PERMISSION_LEVELS = {
  NONE: 0,        // 完全禁用，连看都不能看
  READ: 1,        // 只读，可以执行 --help，但不能修改任何东西
  WRITE: 2,       // 可以写文件、创建目录
  EXECUTE: 3,     // 可以执行任意命令（最常用）
  DANGEROUS: 4,   // 危险操作（需要额外确认）
};
```

数值比较的逻辑很简单：`level >= requiredLevel` 即为通过。但它有个局限：**同类权限无法区分**。比如"可以执行 bash 命令"和"可以执行包含 `sudo` 的 bash 命令"，用同一个 `EXECUTE` 级别就区分不开。这是更高级权限系统的切入点。

### 白名单机制

真正高效的权限系统，第一道关卡是**白名单**。如果每条命令都要走完整套检查流程，性能开销很大，而且用户体验会很差。

白名单里放那些**统计上几乎不会造成破坏**的命令：`echo`、`pwd`、`ls`、`cat`、`head`、`tail`、`grep`、`find`、`wc`、`sort`、`uniq`、`date`、`whoami`。这些命令无论如何调用，都只能产生输出，不会修改任何东西。

Python 实现中，通过提取命令的第一个单词（`first_word = command.strip().split()[0]`）来匹配白名单，这是一个 O(1) 的字典查找，非常快。

## 进阶知识

### 正则模式匹配危险命令

Python 实现用正则表达式来识别危险命令：

```python
DANGEROUS_PATTERNS = [
    re.compile(r"rm\s+-rf\s+/\s"),      # rm -rf / （带空格，防止误匹配 rm -rf /tmp）
    re.compile(r"rm\s+-rf\s+/tmp"),     # rm -rf /tmp （绝对路径也要拦截）
    re.compile(r">\s*/etc/passwd"),     # 任何重定向到 /etc/passwd
    re.compile(r"dd\s+if=.*of=/dev/"),  # dd 写入设备文件
]
```

注意正则中 `/\s`（斜杠后有空格）是关键设计。如果写成 `rm\s+-rf\s+/`，`rm -rf /home/user` 也会被误判。加上空格要求后，只有"根目录"会被拦截，`/home` 这样带子路径的就安全了。

### 交互确认与静默模式

权限系统的用户体验设计也很有讲究：

- **交互模式**：执行危险命令前弹出 `input()` 等待用户确认，适合人类在场的场景
- **静默拒绝**（`auto_approve=False` 且危险命令被检测到）：直接返回 False，不询问
- **完全放行**（`auto_approve=True`）：连危险命令也直接放行，适合 CI/CD 自动化脚本

```python
class PermissionSystem:
    def __init__(self, auto_approve: bool = False):
        # auto_approve = True 时，所有命令直接通过
        # 用于自动化脚本、测试环境
        self.auto_approve = auto_approve
```

## 代码演示

```js
const PERMISSION_LEVELS = {
  NONE: 0,       // 完全禁用
  READ: 1,       // 只能读
  WRITE: 2,      // 可以写
  EXECUTE: 3,   // 可以执行命令
  DANGEROUS: 4, // 危险操作（如删除、格式化）
};

// 权限检查器：基于级别数值的权限模型
class PermissionGuard {
  constructor() {
    this.toolPermissions = new Map();  // toolName → level
    this.defaultLevel = PERMISSION_LEVELS.READ;  // 默认只读
    this.alwaysAllow = new Set(["pwd", "ls", "echo", "whoami"]);  // 白名单
  }

  // 设置某个工具的权限级别
  setPermission(toolName, level) {
    this.toolPermissions.set(toolName, level);
  }

  // 检查权限：数值比较，数字大等于要求即通过
  check(toolName, requiredLevel) {
    // 先查白名单
    if (this.alwaysAllow.has(toolName)) return true;
    // 再看具体配置，没有则用默认值
    const level = this.toolPermissions.get(toolName) ?? this.defaultLevel;
    return level >= requiredLevel;
  }

  // 强制要求权限，不满足则抛异常
  require(toolName, requiredLevel) {
    if (!this.check(toolName, requiredLevel)) {
      throw new Error(
        `权限不足: ${toolName} 需要级别 ${requiredLevel}，` +
        `当前 ${this.toolPermissions.get(toolName) ?? this.defaultLevel}`
      );
    }
  }
}

// 使用示例
const guard = new PermissionGuard();
guard.setPermission("bash", PERMISSION_LEVELS.EXECUTE);      // 允许执行命令
guard.setPermission("file_write", PERMISSION_LEVELS.READ);   // 只读，不允许写
guard.setPermission("delete_tool", PERMISSION_LEVELS.NONE);  // 完全禁用

// 测试
console.log("bash 读权限:", guard.check("bash", PERMISSION_LEVELS.READ));          // true
console.log("bash 写权限:", guard.check("bash", PERMISSION_LEVELS.WRITE));         // false（未配置，按默认只读）
console.log("pwd 白名单:", guard.check("pwd", PERMISSION_LEVELS.READ));            // true（白名单绕过）
console.log("delete_tool:", guard.check("delete_tool", PERMISSION_LEVELS.READ));   // false（显式禁用）
```

## 知识点速查表

| 概念 | 说明 |
|------|------|
| 权限级别 | 用数字表示权限强度，数值比较判断是否通过 |
| 白名单 | 无害命令直接放行，提升性能，减少确认提示 |
| 危险模式 | 正则表达式匹配已知危险命令模式 |
| 交互确认 | 非白名单、非危险命令，弹出用户确认 |
| auto_approve | True 时跳过所有确认，适合自动化场景 |
| 权限守卫模式 | 装饰器 / 策略模式，可组合多种权限策略 |
