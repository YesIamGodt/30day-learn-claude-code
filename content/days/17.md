# Day 17: 任务拆解：把大任务变小步骤

## 这一节要解决什么问题？

当用户对 AI 说"帮我做一个博客系统"，这是一个巨大的任务。AI 如果直接开始做，往往会：
- 不知道从哪开始，犹豫很久
- 做得东一块西一块，没有章法
- 忽略了重要的步骤（比如忘记写测试）
- 在某些细节上过度纠缠，而忽略了整体进度

人类面对大任务时的做法是**任务拆解**：先把它分成"做得了"的子步骤，然后逐个击破。Claude Code 也需要这个能力——让 AI 在动手之前先规划，把大任务变成一串小任务。

任务管理器（TaskManager）就是这个规划能力的载体。它负责记录"有哪些步骤"、"当前在哪一步"、"哪一步完成了"。

## 任务状态机

```
pending ──→ in_progress ──→ completed
    │                        ↑
    │                        │
    └──────→ blocked ────────┘
                    (解除阻塞后继续)

每个任务的生命周期：
1. 创建 → pending（等待执行）
2. 开始 → in_progress（正在进行）
3. 完成 → completed（成功结束）
   或者：遇到阻塞 → blocked（等依赖完成再继续）
```

## 概念图解

```
用户: "帮我做一个博客系统"

任务拆解（由 AI 规划）:

TaskManager
├── Task #1: "设计数据库 Schema"        [completed ✓]
├── Task #2: "实现用户认证 API"          [completed ✓]
├── Task #3: "实现文章 CRUD API"         [in_progress ← 当前]
├── Task #4: "编写前端页面"              [pending]
└── Task #5: "部署到服务器"             [pending]

当前步骤: Task #3
执行完后 → Task #4 → Task #5 → 全部完成 ✓
```

## 基础知识

### 任务状态追踪

```js
class TaskManager {
  constructor() {
    this.tasks = [];         // 所有任务
    this.currentIndex = 0;   // 当前执行到第几个
  }

  // 添加任务（可选：附带子任务列表）
  add(description, subtasks = []) {
    this.tasks.push({ description, subtasks, status: "pending" });
  }

  // 获取下一个待执行的任务
  next() {
    if (this.currentIndex >= this.tasks.length) {
      return null;  // 没有更多任务了
    }
    return this.tasks[this.currentIndex++];
  }

  // 标记任务完成
  complete(taskIndex) {
    if (taskIndex < this.tasks.length) {
      this.tasks[taskIndex].status = "done";
    }
  }

  // 汇报进度
  progress() {
    const done = this.tasks.filter(t => t.status === "done").length;
    return `${done}/${this.tasks.length} 任务完成`;
  }
}
```

### AI 辅助的任务拆解

更强大的做法是让 AI 来做拆解。Claude 本身就是一个很好的任务规划器：

```js
async planWithAI(userTask, client) {
  // 让 AI 生成步骤列表
  const prompt = `把以下任务拆解成 3-7 个具体步骤，每步用一句话描述。
任务：${userTask}
格式示例：
1. 第一步
2. 第二步
...
只返回步骤列表，不要其他文字。`;

  const response = await client.messages.create({
    model: "claude-sonnet-4-7-20250514",
    max_tokens: 500,
    messages: [{ role: "user", content: prompt }],
  });

  const text = response.content[0].text;
  // 从 AI 回复中提取步骤（按行号匹配）
  const steps = text.split("\n").filter(line => /^\d+\./.test(line.trim()));
  for (const step of steps) {
    this.add(step.replace(/^\d+\.\s*/, ""));
  }
  return steps;
}
```

## 进阶知识

### 任务依赖管理

更复杂的场景中，任务之间可能有依赖关系——Task #3 需要等 Task #1 和 Task #2 完成才能开始：

```python
from dataclasses import dataclass, field
from typing import Literal

Status = Literal["pending", "in_progress", "completed", "blocked"]

@dataclass
class Task:
    id: str
    title: str
    status: Status = "pending"
    depends_on: list[str] = field(default_factory=list)  # 依赖的任务 ID

# 判断一个任务是否可以开始：所有依赖都完成了
def can_start(task: Task, completed_ids: set[str]) -> bool:
    return all(dep_id in completed_ids for dep_id in task.depends_on)
```

### 动态状态更新

Python 实现中的 `update()` 方法支持动态字段更新：

```python
def update(self, id: str, **kwargs) -> Task | None:
    task = self._tasks.get(id)
    if not task:
        return None
    for key, value in kwargs.items():
        if hasattr(task, key):          # 只更新存在的字段
            setattr(task, key, value)   # 动态赋值
    task.updated_at = datetime.now()   # 自动刷新时间戳
    return task
```

这样调用方可以用任何字段组合来更新：`manager.update("1", status="completed", metadata={"result": "ok"})`。

## 代码演示

```js
// 任务管理器：管理任务队列，支持 AI 辅助拆解
class TaskManager {
  constructor() {
    this.tasks = [];
    this.currentIndex = 0;
  }

  // 添加一个新任务（可附带子任务）
  add(description, subtasks = []) {
    this.tasks.push({ description, subtasks, status: "pending" });
  }

  // 返回下一个待执行任务（迭代器模式）
  next() {
    if (this.currentIndex >= this.tasks.length) {
      return null;
    }
    return this.tasks[this.currentIndex++];
  }

  // 标记指定索引的任务完成
  complete(taskIndex) {
    if (taskIndex < this.tasks.length) {
      this.tasks[taskIndex].status = "done";
    }
  }

  // 返回进度字符串
  progress() {
    const done = this.tasks.filter(t => t.status === "done").length;
    return `${done}/${this.tasks.length} 任务完成`;
  }

  // 让 AI 帮忙拆解大任务（不需要真实 API key）
  async planWithAI(userTask, client) {
    // 这个提示告诉 AI：只需要返回步骤列表，不要多余的话
    const prompt = `把以下任务拆解成 3-7 个具体步骤，每步用一句话描述：
任务：${userTask}
格式示例：
1. 第一步
2. 第二步
...
只返回步骤列表，不要其他文字。`;

    const response = await client.messages.create({
      model: "claude-sonnet-4-7-20250514",
      max_tokens: 500,
      messages: [{ role: "user", content: prompt }],
    });

    const text = response.content[0].text;
    // 用正则提取所有 "数字." 开头的行
    const steps = text.split("\n").filter(line => /^\d+\./.test(line.trim()));
    for (const step of steps) {
      // 去掉行号，保留步骤描述
      this.add(step.replace(/^\d+\.\s*/, ""));
    }
    return steps;
  }
}

// 测试：手动拆解演示（不需要 AI API）
const manager = new TaskManager();
manager.add("创建项目目录结构", ["src/", "tests/", "README.md"]);
manager.add("实现核心逻辑");
manager.add("编写测试用例");

// 顺序执行所有任务
let task;
while ((task = manager.next()) !== null) {
  const idx = manager.currentIndex - 1;
  console.log("→ 执行:", task.description);
  manager.complete(idx);  // 模拟执行完成后标记完成
}
console.log("✅", manager.progress());
```

## 知识点速查表

| 概念 | 说明 |
|------|------|
| 任务状态机 | pending → in_progress → completed/blocked |
| 任务拆解 | 让 AI 或人类把大任务分成可执行的小步骤 |
| 迭代器模式 | `next()` 方法顺序返回任务，不需要暴露内部列表 |
| 动态更新 | `update(id, **kwargs)` 支持任意字段组合更新 |
| `updated_at` | 自动刷新时间戳，记录最后修改时间 |
| 任务依赖 | 用 `depends_on` 列表声明前置任务，阻塞策略解锁 |

## 面试题

1. **如果用户说"帮我做一个博客系统"，你会如何设计任务拆解的提示词（Prompt）？**提示词需要包含：任务描述（必须具体）、输出格式（步骤编号列表）、约束（只返回步骤，不要解释）、可选（每个步骤的影响或风险估计）。好的提示词能引导 AI 输出"可直接执行"的任务列表，而不是泛泛而谈的描述。

2. **任务管理器如何处理"执行失败"的情况？失败的任务应该重试还是跳过？**这取决于任务类型：不可重复的任务（如"发送邮件"）失败后应该标记 `blocked` 并让用户决定；可以重试的任务（如"编译代码"）可以自动重试 N 次，超过后标记失败。更好的做法是让任务对象自带 `retry_policy` 字段，TaskManager 在执行失败时查询该策略来决定下一步。
