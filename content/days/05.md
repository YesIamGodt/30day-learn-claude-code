      ## BashTool — 执行 Shell 命令

      BashTool 的 Python 实现展示了 asyncio 在子进程管理中的用法。关键在于用 `asyncio.create_subprocess_shell` 创建异步子进程，而不是同步的 `subprocess.run()`：

      ```python
      async def execute(self, command: str, timeout: int = 30) -> str:
          proc = await asyncio.wait_for(
              asyncio.create_subprocess_shell(
                  command,
                  stdout=asyncio.subprocess.PIPE,
                  stderr=asyncio.subprocess.PIPE,
              ),
              timeout=timeout,
          )
          stdout, stderr = await proc.communicate()
          return stdout.decode() + stderr.decode()
      ```

      这段代码有几个细节值得注意：

      1. **`asyncio.create_subprocess_shell` vs `create_subprocess_exec`**：前者把命令字符串传给 shell 解析（支持 `|`, `&&` 等 shell 语法），后者直接执行传入的列表命令（更安全但功能受限）。在 AI Agent 场景下，AI 生成的命令可能包含管道等 shell 语法，所以用 shell 版本。

      2. **`communicate()` 等待两个流都结束**：`stdout` 和 `stderr` 分别存储输出，`communicate()` 会等待两个都读完才返回，避免输出顺序混乱。

      3. **超时控制**：`asyncio.wait_for(..., timeout)` 包装了整个异步操作，超时后抛出 `TimeoutError`，然后调用 `proc.terminate()` 发送 SIGTERM 信号让进程优雅退出，而不是直接 `proc.kill()` 强制杀死（可能导致资源泄漏）。

      ## FileReadTool — 读取文件

      文件读取工具演示了三个重要模式：**异步 IO**、**路径安全检查**、**错误处理**。

      ```python
      async def execute(self, path: str) -> str:
          resolved = Path(path).resolve()  # 转换为绝对路径
          cwd = Path.cwd().resolve()       # 获取当前工作目录
          if not str(resolved).startswith(str(cwd)):
              return f"错误: 禁止访问工作目录之外的文件: {path}"

          try:
              return await asyncio.to_thread(Path(path).read_text)
          except FileNotFoundError:
              return f"错误: 文件不存在: {path}"
          except PermissionError:
              return f"错误: 无权读取: {path}"
      ```

      关键设计：
      - **路径安全检查**：解析后的绝对路径必须以当前工作目录开头。这防止 AI 通过 `../../etc/passwd` 读取系统文件，是最重要的安全防线。
      - **`asyncio.to_thread`**：把同步的 `Path.read_text()` 扔到线程池里执行，不阻塞事件循环。这是 Python 3.9+ 的写法，比手动创建 `ThreadPoolExecutor` 优雅得多。
      - **错误分类返回**：不同错误返回不同的友好提示，而不是统一报 500 错误。这样 AI 能根据错误信息决定下一步行动（比如"文件不存在，那我先创建它"）。

      ## FileWriteTool — 写入文件

      写入文件的逻辑和读取非常相似，但有一个关键区别：**读取只影响 AI 的决策，写入会改变系统状态**。这意味着安全检查更加重要。

      ```python
      async def execute(self, args: tuple[str, str]) -> str:
          path, content = args
          resolved = Path(path).resolve()
          cwd = Path.cwd().resolve()
          if not str(resolved).startswith(str(cwd)):
              return f"错误: 禁止访问工作目录之外的文件: {path}"

          await asyncio.to_thread(Path(path).write_text, content)
          return f"成功写入 {path}，共 {len(content)} 字符"
      ```

      值得注意的是：
      - **返回值是写入的字符数**而不是"成功"，这样 AI 可以验证写入是否符合预期（比如"写入 1000 字符，但内容只有 500 字？说明有问题"）
      - **没有返回文件内容**（否则会被重复写回），只报告操作结果
      - **覆盖而非追加**：当前实现是 `write_text`（覆盖模式），如果要追加模式，可以用 `Path(path).append_text(content)`

# Day 5: 第一个工具：让 AI 执行命令

## 这一节要解决什么问题？

AI 能回答问题，但**不能做事**。这是 AI 和 Agent 的本质区别：AI 是"大脑"，能思考、能推理、能生成文字，但它的思考只停留在文字世界里——它不知道服务器上有哪些文件，不知道项目能不能编译，更不知道某个命令的输出是什么。给它加一个 **Bash 工具**，它就能真正执行命令了——跑脚本、安装依赖、git 操作，统统都能做。

光有 Bash 工具还不够，因为 AI 生成的命令可能不完整，或者执行时报错。还需要 **FileRead 工具** 让 AI 读取项目里的代码，理解上下文；以及 **FileWrite 工具** 让 AI 修改代码或创建新文件。三个工具组合在一起，AI 就能真正"操纵"计算机了：读代码 → 理解现状 → 写修改 → 执行验证。

本节的核心目标是让你理解**工具是怎么被 AI 调用的**：不是 AI 自己去执行 shell，而是 AI 返回一个"调用 bash 工具"的指令，你的程序收到指令后执行它，然后把结果返回给 AI，AI 再决定下一步做什么。**AI 只做决策，工具负责行动**，这是 Agent 架构的核心原则。

## 基础知识

### 1. Node.js 子进程：spawn

`child_process.spawn` 是 Node.js 执行系统命令的核心 API。它创建一个子进程（运行在独立进程中），通过标准输入输出流与父进程通信：

```js
const { spawn } = require("child_process");

// spawn(cmd, args, options)
// cmd: 要执行的命令
// args: 命令参数数组
// options.shell: 是否在 shell 中运行（shell=true 支持管道、重定向等）
const proc = spawn("echo", ["Hello", "World"], { shell: true });

// 收集 stdout 输出（子进程写入的数据会触发 data 事件）
let stdout = "";
proc.stdout.on("data", data => { stdout += data.toString(); });

// 收集 stderr 输出（错误信息走这里）
let stderr = "";
proc.stderr.on("data", data => { stderr += data.toString(); });

// 进程结束时触发 close 事件，code 是退出码
proc.on("close", code => {
  if (code === 0) {
    console.log("成功:", stdout.trim());
  } else {
    console.error("失败:", stderr.trim());
  }
});
```

### 2. Promise 化：spawn → async/await

原生的 `spawn` 是事件驱动的，代码嵌套较深。可以用 Promise 包装，转换成 async/await 风格：

```js
// 把 spawn 包装成 Promise，就可以在 async 函数里用 await 了
function 执行命令(command) {
  return new Promise((resolve, reject) => {
    const proc = spawn("sh", ["-c", command]); // sh -c 支持 shell 语法
    let stdout = "";
    let stderr = "";

    proc.stdout.on("data", data => { stdout += data.toString(); });
    proc.stderr.on("data", data => { stderr += data.toString(); });

    proc.on("close", code => {
      if (code === 0) {
        resolve(stdout.trim() || "(无输出)");
      } else {
        reject(new Error(`命令失败 (${code}): ${stderr.trim()}`));
      }
    });

    proc.on("error", reject); // 进程创建失败（比如命令不存在）
  });
}

// 使用
(async () => {
  const result = await 执行命令("node --version && npm --version");
  console.log(result);
})();
```

### 3. 路径安全检查

**在任何涉及文件路径的工具中，路径安全检查都是必须的。** AI 生成的路径可能是恶意的（读取 `/etc/passwd`），也可能是笔误（访问 `/home/user/../etc/shadow`）。用 `path.resolve` 转换成绝对路径后检查：

```js
const path = require("path");

function 安全读取文件(filePath) {
  // 1. 解析为绝对路径（处理 .. 符号）
  const resolved = path.resolve(filePath);

  // 2. 获取当前工作目录
  const cwd = path.resolve(process.cwd());

  // 3. 检查绝对路径是否在 cwd 范围内
  if (!resolved.startsWith(cwd)) {
    throw new Error(`安全错误: ${filePath} 在工作目录之外`);
  }

  // 4. 安全读取
  return require("fs").readFileSync(resolved, "utf-8");
}
```

## 进阶知识

### 异步子进程 vs 同步子进程

| API | 类型 | 适用场景 |
|-----|------|---------|
| `child_process.spawn` | 异步/事件驱动 | 长时间运行命令、需要实时处理输出 |
| `child_process.exec` | 异步/Promise | 短命令、只需要最终结果 |
| `child_process.execFile` | 同步/异步 | 直接执行可执行文件，不走 shell |
| `child_process.spawnSync` | 同步 | 脚本必须阻塞执行（比如构建脚本） |

Claude Code 选 `spawn` 是因为 AI 可能执行很长的命令（`npm install` 可能需要几分钟），异步方式让程序可以在等待期间处理其他事情。

### 超时控制与进程清理

长时间运行的命令需要设置超时，避免 Agent 永久卡死。超时后的优雅退出也很重要：

```js
async function 带超时的执行(command, timeoutMs = 30000) {
  const proc = spawn("sh", ["-c", command]);

  return new Promise((resolve, reject) => {
    const timer = setTimeout(() => {
      proc.kill("SIGTERM"); // 先尝试优雅终止
      setTimeout(() => {
        if (!proc.killed) proc.kill("SIGKILL"); // 等 2s 不行就强制杀
      }, 2000);
      reject(new Error(`命令超时（${timeoutMs}ms）`));
    }, timeoutMs);

    let stdout = "", stderr = "";
    proc.stdout.on("data", d => stdout += d);
    proc.stderr.on("data", d => stderr += d);
    proc.on("close", code => {
      clearTimeout(timer);
      resolve({ stdout, stderr, code });
    });
  });
}
```

## 代码演示

```js
const { spawn } = require("child_process");

class BashTool {
  get name() { return "bash"; }
  get description() { return "在终端执行命令，返回输出结果"; }

  async execute(command) {
    return new Promise((resolve, reject) => {
      const [cmd, ...args] = command.split(" ");
      const proc = spawn(cmd, args, { shell: true });

      let stdout = "";
      let stderr = "";

      proc.stdout.on("data", data => { stdout += data.toString(); });
      proc.stderr.on("data", data => { stderr += data.toString(); });

      proc.on("close", code => {
        if (code === 0) {
          resolve(stdout.trim() || "(无输出)");
        } else {
          reject(new Error(`命令失败 (${code}): ${stderr.trim()}`));
        }
      });

      proc.on("error", reject);
    });
  }
}

// 测试
(async () => {
  const tool = new BashTool();
  try {
    const result = await tool.execute("echo 'Hello from bash!'");
    console.log("命令输出:", result);
  } catch (e) {
    console.error("执行失败:", e.message);
  }
})();
```

## 知识点速查表

| 概念 | 说明 | 示例 |
|------|------|------|
| `child_process.spawn` | Node.js 创建子进程的核心 API | `spawn("node", ["index.js"])` |
| `shell: true` | 在 shell 中执行，支持管道/重定向 | `echo a \| grep b` |
| `proc.stdout.on("data")` | 监听子进程标准输出 | 实时获取命令输出 |
| `proc.on("close", code)` | 进程退出时回调，code=0 成功 | 错误码非 0 要处理 |
| 路径安全检查 | 绝对路径必须在 cwd 内 | `resolved.startsWith(cwd)` |
| `path.resolve()` | 解析相对路径为绝对路径 | 处理 `../` 等符号 |
| `SIGTERM` vs `SIGKILL` | 优雅终止 vs 强制杀死 | 先 TERM 等 2s，不行再 KILL |
| `asyncio.to_thread` | Python 把同步 IO 扔线程池 | 不阻塞事件循环 |
